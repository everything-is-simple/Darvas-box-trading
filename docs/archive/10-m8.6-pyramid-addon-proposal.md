## 1. 立项依据

### 1.1 问题：加码几乎不发生

2014/2015/2016/2018 四年回放的 pyramid 信号数：

| 年份 | breakout | pyramid | 持仓数 | 触发加码持仓 |
|------|----------|---------|--------|-------------|
| 2014 | 17 | **2** | 17 | 2（占 12%） |
| 2015 | 9 | **0** | 9 | 0 |
| 2016 | 8 | **0** | 7 | 0 |
| 2018 | 11 | **0** | 10 | 0 |

2014 那 2 笔加码贡献了全年 **85%** 的盈亏（125,567 / 148,111）——
加码是盈利主力，却极少发生。

### 1.2 根因：只实现了达瓦斯两条加码规则中的一条

达瓦斯原书存在**两种**加码形态（《我如何在股市赚了200万》）：

**① 跨箱体加码**（罗瑞拉德，OCR line 1447）：
```
28.75 → 35 → 36.5 → 38.625   （每次进入新箱体后加码，共 +34%）
```
→ 本系统已实现：`signal.go` 中"持仓股新箱体 `broken_up` → pyramid"。

**② 同一箱体内连续补仓**（布鲁斯，OCR line 1504）：
> 我决定充分利用现有的 50% 保证金比例的有利条件。**当我看到公司股价没有触及
> 止损位后，我开始继续补仓**，每一笔买单都附设了止损位，价格在 47～48 美元之间。

```
50.75 → 51.125 → 51.75 → 52.75 → 53.625   （5 笔连续加码，总区间 +5.7%）
```
→ **本系统未实现**。这就是加码信号稀少的直接原因：只等"新箱体形成"这条慢通道，
而多数股票突破后还没走出新箱体就已止损/被清仓。

### 1.3 量化边界的来源（不是缝合）

《简简单单做股票》（2018）第二章第六个心得（OCR line 1897）：

> 关于短期仓和中期仓的进入时机：短期仓介入，第二天盈利了，中期仓就进入。
> ……他对利弗莫尔的金字塔加仓方式做了修正，**大意是加仓要在买点上涨 5% 以内**。

判断：
- **"未触及止损就补仓"是达瓦斯原书规则**（不是外来理论）；
- **"买点上方 5% 以内"是欧奈尔对该类加仓的量化边界**，且与布鲁斯实际加码区间
  （+5.7%）吻合；
- 二者组合 = 把达瓦斯第②条补全为可执行规则，**未引入箱体理论之外的任何概念**
  （不使用均线/MACD/回调双底等）。
- 明确**不采纳**该书的其他内容：强势股回调双底买点（与"突破买入"冲突）、
  分批卖出（破坏"止损只升不降 + 整体清仓"结构）。

## 2. 规则定义

### 2.1 现状（单通道）

```
持仓 + 新箱体今日 broken_up（BrokenDate==当日）+ legN < maxlegs(3)
  → SignalPyramid（腿2/3）
```

### 2.2 新增（第②通道，addon）

```
持仓（StageHolding）
且 today.Low > position.stop_price          ← C1 未触及止损（达瓦斯原话）
且 today.Close >= 上次成交价（首腿/最近加码）  ← C2 顺势加码，绝不摊低成本
且 today.Close <= 首腿成交价 × (1 + 0.05)    ← C3 买点上方5%内（欧奈尔边界）
且 legN < maxlegs(3)                        ← C4 腿数上限（不变，避免改DB约束）
且 当日无 stop / failed_breakout 信号        ← C5 更高优先级信号优先（天然满足）
  → SignalPyramid，payload.trigger = "addon"
```

设计要点：
- **C1 用 `today.Low > stop`**（盘中最低都没碰止损），最严格地对应"没有触及止损位"；
- **C2 防止摊低亏损**：达瓦斯明确"绝不要摊低亏损的头寸"，加码价不得低于上次成交价；
- **C3 防止追高**：5% 是欧奈尔边界，也把布鲁斯 5 笔（+5.7%）圈住；
- **C4 保持 3 腿**：`position_leg.leg_no CHECK IN (1,2,3)` 与 `plan_order.leg_no`
  同为 3 值约束，扩到 5 腿需新迁移重建表——**第一版不动 schema**，先验证触发条件本身；
- 首次事件语义不变：同一天只发一次；每次成交后 legN+1，故最多连续 2 个交易日各加一次。

### 2.3 伪代码（对应 `internal/signal/signal.go` `evalOne`）

```go
// 在现有 broken_up 判定之后、return nil 之前插入（第 2 通道）
if w.Stage == contract.StageHolding {
    if s := e.checkAddon(w.Code, date, today, prev); s != nil {
        return s
    }
}

// checkAddon 达瓦斯第②条：未触及止损 + 买点上方5%内 → 加码
func (e *Engine) checkAddon(code, date string, today, prev contract.DailyBar) *contract.Signal {
    pos, err := e.st.TradeRepo.PositionByCode(code)
    if err != nil || pos == nil || pos.Status != "open" || pos.Qty <= 0 {
        return nil
    }
    if pos.StopPrice <= 0 || today.Low <= pos.StopPrice {
        return nil                          // C1 盘中触及/跌破止损 → 不加
    }
    legs, _ := e.st.TradeRepo.LegsByPosition(pos.ID)
    legN := len(legs)
    maxLegs := e.st.ParamRepo.GetInt("risk.maxlegs", 3)
    if legN >= maxLegs {
        return nil                          // C4 腿满
    }
    // 首腿成交价 + 最近一次腿成交价
    leg1Price, lastPrice := 0.0, 0.0
    for _, lg := range legs {
        if n, _ := lg["leg_no"].(int64); n == 1 {
            leg1Price, _ = lg["price"].(float64)
        }
        if p, _ := lg["price"].(float64); p > lastPrice {
            lastPrice = p                   // 最近成交价取最高腿价（顺势）
        }
    }
    if leg1Price <= 0 {
        return nil
    }
    premium := e.st.ParamRepo.GetFloat("risk.addon_max_premium", 0.05)
    if today.Close < lastPrice {             // C2 不摊低
        return nil
    }
    if today.Close > leg1Price*(1+premium) { // C3 不追高
        return nil
    }
    return &contract.Signal{
        Date: date, Code: code, Type: contract.SignalPyramid,
        ClosePx: today.Close, BoxLevel: leg1Price,
        Payload: map[string]any{
            "trigger": "addon", "leg1_price": leg1Price,
            "last_leg_price": lastPrice, "stop_price": pos.StopPrice,
            "addon_max_premium": premium, "leg_no": legN + 1,
        },
    }
}
```

> 注：`LegsByPosition` 返回 `[]map[string]any`（见 `repo_trade.go:462`），
> 取值键为 `leg_no` / `price`（int64 / float64）。

### 2.4 与 planner 的衔接

- 新信号仍走 `SignalPyramid` 类型，`planner.buyOrder` 现有腿号逻辑不变：
  有持仓 → 腿3（`leg = 3`）。**注意**：现有 planner 只有"腿2=无持仓"、"腿3=有持仓"两档，
  第②通道的第二次加码（legN=2 → 新腿 = 3）会与已有 leg3 撞号——`ledger.applyBuy`
  已有"腿号冲突顺延"逻辑，但顺延后的 leg_no 可能 >3 被 CHECK 拒绝。
  **处理**：C 组第一版限制"第②通道至多加一次"（legN==1 时才生效），
  避免撞上 leg3 约束；若验证有效，再立 P1 讨论扩腿。

## 5. 预期对比指标（固定，先于结果设定）

| 指标 | 定义 | 预期方向 |
|------|------|---------|
| **pyramid 信号数** | signal.type=pyramid 计数 | C > B ≈ A（核心验证点） |
| **加码触发率** | 有加码持仓 / 总持仓 | C 显著 > A/B |
| **加码贡献占比** | 加码持仓 realized_pnl / 总 pnl | C 更高（布鲁斯式放大） |
| **总收益** | 期末权益 / 期初 − 1 | C > B > A（预期） |
| **最大回撤** | equity.drawdown 最小值 | C 略差（仓位更重更早） |
| **假突破损失** | failed_breakout 亏损合计 | C 可能放大（须监控） |
| **平均持仓天数** | 平仓日 − 开仓日 | C 可能缩短（止损上移更快） |

判定标准（先验）：
- **成功** = 收益显著提升（≥ +2 个百分点）且回撤未恶化超 50% 且假突破损失未翻倍；
- **失败** = 收益无改善，或假突破损失翻倍；
- 无论成败，**只输出结论不给单点最优**（2017 单年样本，防过拟合）。

## 6. 风险与纪律

| 风险 | 应对 |
|------|------|
| 加码过早放大假突破损失 | C1（盘中未触损）+ C3（5% 边界）双重过滤；实测监控 failed_breakout 损失 |
| 腿号 CHECK 约束（3 值） | 第一版限制 addon 至多加一次（legN==1）；扩腿另立 P1 |
| 违反"单一理论" | 不引入任何箱体理论外概念；第②条有达瓦斯原书出处（line 1504） |
| 观察期规则冻结 | 只跑 scratch 库；生产 `darvas.db` 与 `serve` 不受影响；参数不进生产 param 表 |
| 4 年样本少/单年样本 | 只出敏感性结论；需 2019-2021 补充验证后方可考虑上线 |
