# E17 回测耗时诊断（2026-10-25）

> 触发：qoder 按 docs/27 prompt 跑 E17（2014-2018），2014 单年耗时约 10 小时，怀疑回测脚本有问题。
> 结论：**E17 代码逻辑正确，慢的根源不是代码写错，而是 boxscan 在两个交易日出现异常耗时（合计约 7 小时）。**

---

## 1. 结论摘要

| 项 | 结论 |
|---|---|
| E17 ladder 代码是否正确 | **正确**。按 docs/27 §3.8 实现：0-5%/5-10%/10-20%/20-40% 分档，>40% 拒买；`--set` 只写 scratch 库，不污染源库/生产库 |
| 2014 单年实际耗时 | 约 10 小时（13:41 → 23:39） |
| 主要耗时点 | **boxscan 在 2014-07-03（4h5m）与 2014-08-04（3h5m）两天异常**，合计约 7h10m，占全年约 68% |
| 是否算法/代码退化 | **否**。同样日期、同样 codes hit / boxes 数，p05 基线 boxscan 只要约 40 秒 |
| 2015 当前状态 | 正常运行中，boxscan 为秒级~2 分钟，未出现异常 |

一句话：**不是脚本写错，而是运行环境/磁盘 I/O 层面的偶发异常，叠加 boxscan 本身逐日全市场扫描的固有开销。**

## 2. 证据

### 2.1 基线 vs E17 总耗时

| 回测 | 2014 耗时 | 五年合计 |
|---|---|---|
| p05 基线（10-23，darvas_p05.exe） | 2h55m | 13h27m |
| E17（10-24，darvas_e17.exe） | **约 10h** | 2015-2018 进行中 |

p05 各年：2014=2h55m、2015=2h10m、2016=1h42m、2017=2h12m、2018=4h28m。

### 2.2 E17 2014 慢在 boxscan 的两天

`var/bt/e17_2014.log` 中带「小时」的耗时只有这两条：

```
[boxscan] 2026/10/24 18:48:48 rescan-incr 2014-07-03: 1123/5363 codes hit, 39515 boxes, 4h5m16s
[boxscan] 2026/10/24 22:29:23 rescan-incr 2014-08-04: 1017/5363 codes hit, 35452 boxes, 3h5m21s
```

其余日期 boxscan 均为秒级到约 2 分钟，与 p05 相当。

对照 p05 同一日期（`var/bt/p05_2014.log`）：

```
2014-07-03: 1121/5363 codes hit, 39479 boxes, 41s
2014-08-04: 1011/5363 codes hit, 35275 boxes, 31s
```

**codes hit / boxes 数量几乎相同，耗时却差约 360 倍** → 不是数据量或算法问题，而是运行环境异常。

### 2.3 qoder 代码改动核验（git diff vs HEAD，未提交）

改动 6 文件（+351/-28），其中与正确性相关的关键点：

- `internal/planner/planner.go`
  - `newHighLadder` 读取 `pos.newhigh_ladder/lookback/cutoff/units.t1..t4`；
  - `tierFor` 分档边界正确：`>cutoff` 拒买，`<5`→t1，`<10`→t2，`<20`→t3，否则 t4；

结论：**E17 的实现没有引入导致 10 小时级慢速的代码缺陷。**

## 3. 为什么 boxscan 会在特定日期卡数小时

`box.RescanIncremental` 每天都做两类工作：

1. 跟踪池全量重放；
2. 全市场预过滤后，对命中股票重算箱体并 `UpsertBoxes` 落库。

这两天的工作量（codes hit、boxes）与 p05 基本一致，因此 4 小时级耗时只能来自外部环境，例如：

- 同机并发任务争抢磁盘 I/O（其他回测/分析脚本/大批量读写）；
- 磁盘或杀毒软件导致的极端写入延迟；
- SQLite 在特定写入阶段的异常卡顿（需现场 profiling 才能进一步定位）。

**目前没有证据表明需要改 E17 业务代码。** 2015 当前正常运行也支持这一判断。

## 4. 建议

### 4.1 立即执行（不改代码）

1. **不要并行跑多个回测/重型分析任务**。当前机器上只有一个 `darvas_e17` 进程，保持串行。
2. **让 2015-2018 继续跑完**（`scripts/run_e17_rest.bat` 已在跑）。2014 的 +182,188 结果有效，无需重跑。
3. 跑 2008 年样本外时，同样串行执行，并先确认 `full_hist_10pct.db` 覆盖 2008 年。

### 4.2 若还要压缩机时（后续优化，非必须）

- 给 boxscan 增加「单日耗时 + 命中数」告警，异常天可快速定位；
- 评估 boxscan 是否可对「未命中预过滤」的股票跳过更多工作；
- 避免把多个大型 scratch 库同时放在同一磁盘高负载时段写入。
