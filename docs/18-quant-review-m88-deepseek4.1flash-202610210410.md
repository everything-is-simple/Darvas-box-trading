## 零、结论先行

**三句话：**

1. **五年回测的 +25.1 万利润（+25.1%）里有 171% 来自 2 笔成交**——sz002640（2014，成交价 27.80 vs 计划买点 17.10，**+63%**）、sz300168（2015，成交价 97.00 vs 计划买点 36.98，**+162%**）。剔除这两笔，五年合计 **-178,908（-17.89%）**。
2. 这两笔不是模型误差，是**执行层缺一个跳空上限**的必然产物：71 笔买腿里 **63.4% 成交价高于计划买点 5% 以上**，中位 **+7.35%**，8 笔超过 +50%。同时它把首腿止损距离从设计的 5.8% 静默放大到**中位 11.47%**——B1「紧止损」在实际成交里不成立。
3. **生产库当前就躺着一笔同类订单**：sh600825，箱顶 5.10（7-07 确认），10-19 现价 15.58（**+205%**），挂单 5.253×9,500 股。只因 2026-10-20 数据缺失、整链被跳过才没成交。这笔单若成交：实际敞口 14.8% 权益（设计 5%）、止损位 4.947（**-68%**）。

**因此我的判定是：不建议转正，且不建议以当前状态实盘。** 前两份报告的 P0 清单（回测验收、口径分裂、幸存者偏差披露、转正决策）**全部错过了真正的阻断项**——它们把「回测数字好不好看」当成验收对象，而没验「这些成交价在真实市场里能不能拿到」。

## 一、系统溯源：机制层忠实，但有三处「名义实现 ≠ 实际行为」

前两份报告的逐条映射（三日法则、停损买单、止损只升不降、破位清仓、两亏拉黑、5-8 支上限）我抽查后**认可**，不再重复。以下只列我复核出的**新增偏差**——共同特征是：文档描述的是设计意图，实际行为是另一回事。

| # | 项目 | 文档/设计意图 | 代码位置 | 实际行为（实测） | 性质 |
|---|---|---|---|---|---|
| D1 | **首腿紧止损（B1）** | 止损=突破点上轨×0.97，即距成交价约 **5.8%** | `planner.go:319-321` | 成交价常远高于触发价 → 实际止损距离**中位 11.47%、均值 16.06%、22/57 腿 >15%、最宽 64.1%** | 设计被成交模型击穿 |

## 二、演化脉络：两次真实的进步，一次验证口径的偷换

不重复编年史（archive/16 §2 已足够），只给三条判断：

**（1）M8.7 证伪并干净退役——这是整个项目最好的方法论示范。**
「箱体法无法标指数」被 sh000001 全历史 0 个 confirmed 箱体的硬数据证伪，随即退役、不修补、不降级保留。这条纪律值得保留。

**（2）M8.8 的单位制是真进步，我认可它独立于收益的价值。**
现金低点五年 46.9/54.6/52.3/73.9/60.0%，对照 M8.6 的 -22.2%（透支）与 12.8%（破 30% 红线）。**「永远留 30% 现金」这条宪法级约束，M8.6 数学上做不到，M8.8 做到了。** 这一条与收益无关，是可用性的硬门槛。

**（3）但 M8.8 的「体制标定」在验证阶段换了口径。**
- 立项诊断（`scripts/dbg_breadth`）用 `box.Scan` 对 2004-2025 全历史做**纯函数折叠**，得到 2017 年 0 牛日；
- 上线行为用 `box` 表的**增量写入 + 状态修订**，得到 2017 年 78 牛日。

两者不是同一条序列。原因在 `BreadthAgg`（`repo_box.go:251-286`）只读 `box.status IN ('broken_up','broken_down')` 的**最终状态**，而箱体在后续扫描中会被改写为 `invalid`（2014 年末 `invalid` 箱体 32,095 个，是 `broken_up` 的 1.7 倍）。于是「同一历史日期的宽度比率」会随扫描时点变化。

这带来一个必须写进验收的后果：**宽度信号不可离线复现**。我用最终状态的 box 表重算，得到 2017 年 30 个牛日；日志是 78；archive/13 是 0。三个数字，同一件事。任何「事后归因」都会失真。

## 三、失败复盘：十种死因之外，补第十一种

malf-archived 25 个废弃目录 + 根级 `STRATEGY-PROMPT-v1-enhanced.md` 遗书，前两份归纳的十种死因（规则误读、数据质量、参数过拟合、回测口径不一致、行情适配、执行与仓位管理……）我基本认同，且当前系统用「宪法 + SSoT + 门禁 + as-of 差分」免疫了其中九种，这部分不必推翻。

**我补的第十一种死因：把「执行模型」当成回测的附属品，而不是一等公民。**

这一轮的直接证据链：

| 环节 | 应有 | 实际 | 后果 |
|---|---|---|---|
| 进场 | 突破 +3% 买入，追高有限 | 无上限，跳空按开盘成交 | 63.4% 的进场高于计划价，中位 +7.35% |
| 初始风险 | 5.8% | 中位 11.47%，22/57 >15% | 单笔风险敞口是设计值的 2 倍 |
| 收益归因 | 多笔累积 | 2 笔占 171% | 结论建立在 2 个样本上 |
| 复权 | 精确复权 | 除权日按昨收强平（`match.go:54-73`） | 赢家被制度性砍断，趋势跟随的连续性受损 |
| 成本 | 佣金+印花税+过户费 | 已实现（`match.go:171-179`），但**无滑点** | 逐年换手 20-40 笔，滑点缺失约 0.3-0.8%/年 |

**可复用教训**：一套回测系统里，`match` 的优先级应等同于 `box`。本项目对箱体引擎写了 778 行测试、做了三次差分审计；对撮合器只有 `match_test.go` 的触发判定，**没有一条测试约束「成交价不能离计划价太远」**。而恰恰是这里漏掉了 171% 的利润来源。

**P0-3｜生产跟踪池状态污染（违反 5-8 支核心纪律）**
```
watch: watching=114, pending=7, exited=4  → active=121
pool.maxwatch = 8
```
114 支全部 `added_date=2026-10-16`，此后每次 poolsync 都命中 `repo_pool.go`/`pool.go:72-77` 的「跟踪池满（121≥8），跳过入池」直接 break。**池子被冻结在 10-16 的快照上**，此后不再换血。

修复：清池重建 + 把 `active ≤ maxwatch` 加进 `check_consistency.py`（当前 47 键检查全绿，但没有状态不变量检查）。

**P0-4｜生产跑的不是被验收的那个策略**
`plan_order.reason_json` 实测字段：
```
{"probe_max_pct":0.05,"risk_pct":0.01,"scale":5,"max_qty":6700,"equity":1000000,...}
```
这是 M8.6/M8.7 的**固定百分比 + 风险公式**仓位；M8.8 单位制的字段应是 `unit_value / units / budget_bucket / regime`（对照 `planner.go:437-442`）。数值也对得上：每单 ≈ 5% × 100 万 ÷ trigger，而非 1 unit = 2%。
所以「M8.8 转正」从未发生，现状是**回测 M8.8 / 生产 M8.6 的混跑状态**，前两份报告把它当成「生产已稳定运行，上线不被阻断」，属于误判。

**P0-5｜同批次重复卖出单（rc=1 的真实根因）**
前两份报告把 2017/2018 的 `rc=1` 归因为「M8.3 复权清仓联动边界问题」——**实测不是**。
`sh600578 2017-05-09` 的订单链：
```
order 15  plan 2017-05-08  sell  trigger 4.2195  signal=stop
order 16  plan 2017-05-08  sell  trigger 4.21    signal=time_stop_3weeks   ← 同一仓位第 2 张卖单
```
`sz002454 2018-04-09` 同型（order 4 stop / order 5 time_stop）。
根因在 `planner.go:106-138`：`pendingSell` 只在开头从 DB 读一次，**在生成 stop 卖单后没有回写 `pendingSell[s.Code]=true`**，于是 B2⑤「3 周不获利」循环（`planner.go:143-170`）对同一仓位再生成一张卖单。次日第一张成交清仓，第二张必然「卖出成交但无持仓」。
影响：不改变收益（只成交一张），但 rc=1 会让整年回测返回非零，**掩盖真正的失败**。修复为一行。
