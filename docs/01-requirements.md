# 01 · 需求分析（REQUIREMENTS）

> 项目：Darvas-box-trading —— 达瓦斯箱体交易系统
> 版本：v1.3（2026-10-17 初版；2026-10-18 修订一 M8 回放器立项；
> 修订二 时间表后移；修订三 时刻集中一处管理——§4 唯一事实源，代码/CLI/GUI/测试/C4 派生锁定）
> 理论依据：`docs/00-darvas-theory.md`（唯一理论来源）

---

## 1. 项目定位（一句话）

**把达瓦斯的自律变成软件**：每个交易日在明确划分的时间点做固定的事情——初步选股形成股票池 → 跟踪股票池直到出现交易机会 → 用交易计划回答六问 → 周而复始。

### 六问（系统必须每天给出书面答案）

| # | 问题 | 答案产出物 |
|---|------|-----------|
| 1 | 买什么 | 候选池 + 跟踪池中的突破股票清单 |
| 2 | 何时买 | 明日停损买单触发价（箱体上轨上方） |
| 3 | 买多少 | 风险仓位公式计算出的股数（分3腿金字塔） |
| 4 | 卖什么 | 跌破箱体下轨的持仓清单 |
| 5 | 何时卖 | 明日止损卖单触发价（最新箱体下轨下方） |
| 6 | 卖多少 | 全部（达瓦斯纪律：一次全出） |

## 2. 用户与使用场景

- **单一用户**（个人投资者），Windows桌面，本地运行，无云端依赖
- 用户每天的操作动线：
  1. 15:30左右在通达信客户端点击「下载数据」（当日数据收盘后约15:30才可下载）
  2. 16:00系统自动开跑盘后流水线（screen初选约17:00完成）
  3. 17:00-18:30浏览候选池/跟踪池（screen/poolsync完成后）→（可选）人工标注基本面复核
  4. 19:00《明日交易计划》随日报落盘（习惯查看时点19:30）
  5. 次日08:00打开计划核对，08:20券商APP挂集合竞价单/条件单
  6. 成交当日12:30（午间休市）录入上午成交；下午触发的成交最迟次日12:30补录
     （半自动，券商复制粘贴 / 炒股手CSV）
- **每周六08:00**：周报（箱体全景、账本核算、纪律审计）

### 非用户（排除）

- 不支持多用户、不支持实盘自动下单（只生成计划，人工执行）；不做**通用**回测平台——
  2026-10-18 M8 立项修订：允许内置回放器 `darvas backtest`（重放生产流水线本身，
  详见 §9 与 PROMPT.md P4/M8）

## 3. 数据源需求

| 数据 | 来源 | 说明 |
|------|------|------|
| 日线行情（OHLCV） | `H:\new_tdx64\vipdoc\{sh,sz}\lday\*.day` | 11942个文件，32字节/条，**已验证更新至2026-10-16**，用户通达信每日盘后更新 |
| 备用日线 | `H:\2025炒股手训练软件\stockdata\day` | 备援数据源（P2接入） |
| 参考库 | `H:\malf-data-old\*.duckdb` | 仅作对账参考，**不作为运行时依赖** |
| 财务数据 | 无自动来源 | 基本面为人工复核项（见理论§6） |

### 数据同步需求

- D1 全量导入：首次运行将全部.day文件导入SQLite（目标<10分钟）
- D2 增量同步：此后每日只导入「文件修改时间在当日」的增量记录
- D3 质量校验：坏记录跳过并记日志；单日导入量异常（如<1000只更新）时告警
- D4 幂等：同日重复导入不产生重复数据（code+date主键约束）

## 4. 核心需求：每日时间表（Daily Schedule）

> 这是整个系统的心脏。调度器按交易日历在固定时间点触发固定任务，每个任务有唯一编号、唯一产出物、可独立重跑。

### 4.1 T日盘后流水线（主流程）

> **本表是全系统时刻的唯一事实源**（2026-10-18 v1.3 起）：调度器 `scheduler.Schedule`
> 与此同步，CLI usage/serve 横幅、GUI 心跳、测试用例、一致性检查 C4 全部由其派生，
> 禁止他处硬编码时刻。改时点 = 改本表 + 改 `internal/scheduler/scheduler.go`，其余自动跟随。

| 时刻 | 任务ID | 任务 | 输入 | 产出物 | 失败处理 |
|------|--------|------|------|--------|---------|
| 16:00 | `ingest` | 数据同步 | TDX vipdoc | `daily_bar`增量 + 运行日志 | 重试3次；数据陈旧（最新交易日≠T日）则阻断后续 |
| 16:30 | `boxscan` | 全市场箱体重算 | `daily_bar` | `box`表（forming/confirmed/broken） | 失败重跑；可只重算跟踪池+候选池以降级 |
| 17:00 | `screen` | 初选筛选 | `box`+`daily_bar` | `candidate_pool`当日快照 | 失败重跑 |
| 17:30 | `poolsync` | 跟踪池状态迁移 | `candidate_pool`+`watch` | `watch`表更新（入池/升阶/出池） | 失败重跑 |
| 18:00 | `signal` | 信号判定 | `watch`+`box`+持仓 | `signal`表（突破/加码/止损/跌破） | 失败重跑 |
| 18:30 | `plan` | 交易计划生成 | `signal`+`position`+`param` | `trade_plan`+`plan_order`（六问答案） | **必须成功**，失败则红色告警（无计划次日无法操作） |
| 19:00 | `report` | 决策日报 | 以上全部 | HTML日报 `var/reports/daily_YYYYMMDD.html` | 失败不影响主流程 |

依赖链：`ingest → boxscan → screen → poolsync → signal → plan → report`（严格串行）。

### 4.2 T+1日盘前（人工环节，系统辅助）

| 时刻 | 动作 | 系统支持 |
|------|------|---------|
| 08:00 | 打开《明日交易计划》，核对触发价/委托价 | GUI计划视图 / HTML文件 |
| 08:20 | 券商APP挂集合竞价单/条件单（券商9:15竞价开始自动申报预埋单） | 每笔订单给出：代码、方向、触发价、委托价、数量、有效期、备注 |
| 09:25 | 集合竞价结束，确认开盘价 | 计划页显示触发价 vs 开盘价参考 |
| 盘中 | **不盯盘**（达瓦斯纪律） | 无盘中推送（可选：收盘前5分钟提醒落袋检查） |
| 12:30 | 核对上午成交并录入（午间休市；下午成交最迟次日12:30补录） | 盯守自动化20:00兜底提醒 |
| 15:30 | 通达信下载数据（当日数据收盘后约15:30才可下载） | 盯守自动化20:00检查新鲜度 |

### 4.3 周度任务（周六）

| 时刻 | 任务ID | 任务 | 产出物 |
|------|--------|------|--------|
| 08:00 | `weekly` | 周度复盘 | 周报HTML：持仓箱体阶梯全景、周盈亏、权益曲线、纪律审计（有无违规挂单/未止损） |

### 4.4 交易日历

- 使用上证指数（sh000001）的`daily_bar`日期序列作为交易日历权威来源
- 非交易日跳过调度；用户也可手动 `darvas run --date 2026-10-16` 补跑任意交易日

## 5. 功能需求清单（FR）

### 5.1 数据层

- **FR-101** 读取TDX `.day`二进制格式（32字节记录：date/open/high/low/close/amount/volume，价格×100）
- **FR-102** 全量/增量导入至SQLite，幂等可重跑
- **FR-103** 识别指数/主板/创业板/科创板/ST（按代码规则+名称规则），维护`security`表
- **FR-104** 数据质量日报：更新股票数、坏记录数、日期连续性检查

### 5.2 箱体引擎

- **FR-201** 三日法则箱体识别（上轨/下轨状态机，详见理论§3）
- **FR-202** 箱体阶梯链：`box.prev_box_id` 自引用，构成个股箱体历史
- **FR-203** 突破判定：收盘>上轨×1.03 且 当日量≥50日均量×2 且 非一字板
- **FR-204** 箱体作废规则：下轨确立前创新高→箱体作废重计
- **FR-205** 对任意股票输出箱体全景JSON（供GUI画阶梯图）

### 5.3 初选与跟踪池

- **FR-301** 四条件初选（流动性/RS/放量/箱体形态），输出打分排序的候选池快照
- **FR-302** 跟踪池状态机：`candidate → watching → pending → holding → exited`，迁移规则见ERD
- **FR-303** 出池规则：箱体broken_down / 连续4箱不涨（横盘过久）/ 人工移除
- **FR-304** 人工复核界面：基本面✓/✗标注、备注

### 5.4 信号与交易计划

- **FR-401** 四类信号：`breakout`（突破，买）、`pyramid`（加码，买）、`stop`（跌破下轨，卖）、`failed_breakout`（突破失败，卖）
- **FR-402** 停损买单计划：触发价=箱体上轨×1.03（参数化）
- **FR-403** 止损卖单计划：触发价=最新箱体下轨×0.97（参数化）
- **FR-404** 仓位计算：`qty = floor(权益×风险% / (触发价−止损价) / 100)×100`（A股整手）
- **FR-405** 金字塔腿管理：同股最多3腿；第2/3腿需新箱体确认
- **FR-406** 计划导出：HTML + Excel（可直接照着挂单的清单）

### 5.5 持仓与账本

- **FR-501** 成交录入（半自动：粘贴券商成交文本，解析日期/价格/数量/费用）
- **FR-502** 持仓视图：每持仓关联当前箱体、最新止损位、浮盈浮亏、腿明细
- **FR-503** 每日权益快照：现金/市值/总额/回撤
- **FR-504** 账本恒等式校验：`现金 + Σ持仓市值 = 总权益`，不平则红色告警

### 5.6 调度与运行

- **FR-601** 内置调度器：常驻进程按§4时间表触发任务；错过时刻（电脑关机）启动时补跑
- **FR-602** CLI：`darvas run / ingest / boxscan / screen / plan / report / gui` 子命令，支持`--date`
- **FR-603** 任务运行日志：每任务起止时间/状态/错误，GUI可见
- **FR-604** 参数热调：放量倍数、RS窗口、风险系数、箱体宽度等存`param`表，GUI可改

### 5.7 GUI（桌面程序）

- **FR-701** 主视图四标签页：**今日流程**（任务心跳+六问答案）、**股票池**（候选/跟踪表格）、**持仓**（阶梯止损视图）、**计划**（明日订单清单）
- **FR-702** 个股详情：K线图+箱体阶梯叠加渲染
- **FR-703** 数据导入后自动刷新；所有列表支持代码/名称搜索
- **FR-704** 单可执行文件分发：exe + db 两个文件拷走即用（同平台）

## 7. 非功能需求（NFR）

| # | 需求 | 目标 |
|---|------|------|
| NFR-1 | 全流程性能 | 盘后流水线全程（1.2万只股票）≤ 5分钟（boxscan为热点，需增量化） |
| NFR-2 | 可移植性 | 目标机=同平台Windows x64；拷贝`darvas.exe`+`darvas.db`即可运行，零安装 |
| NFR-3 | 数据安全 | SQLite WAL模式；每日自动备份db至`var/backup/`，保留30份 |
| NFR-4 | 可恢复性 | 任一任务可单独重跑且幂等；崩溃不损坏账本（事务） |
| NFR-5 | 可审计性 | 每个信号、每笔订单、每次参数修改都留痕（表见ERD） |
| NFR-6 | 单文件构建 | `go build`产出单一exe（纯Go SQLite驱动，无CGO） |

## 9. 明确不做（Negative Requirements）

- ❌ 自动下单（只出计划，人工挂单）
- ❌ 盘中/tick级任何逻辑
- ❌ 多策略/多理论（见理论§9单一理论原则）
- ❌ 多用户/网络服务
- ❌ 通用回测平台 / 外部回测框架（backtrader、vectorbt、backtesting.py 等——2026-10-18 判决：不引入。
  理由：规则需在 Python 重写=双重事实源；A股摩擦（T+1/涨跌停/整手/税费）框架不送；引入 Python 运行时破坏单 exe 分发）
- ✅ 内置回放器 `darvas backtest`（M8 修订，2026-10-18 立项）：scratch 测试库上按交易日历
  重放 as-of 六任务链（生产代码路径、规则零重写）+ 模拟撮合器（A股摩擦）+ 分体制（牛/熊/猴）报告。
  定位仅限引擎与纪律验证，不是回测产品；观察期内规则冻结，回放只产出问题清单。
