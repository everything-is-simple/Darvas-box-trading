## 1. 定位与目标

**一句话**：把「人工把券商成交单贴回系统」这一步，替换成「用当日 OHLC 模拟停损单是否触发」，
触发则生成 `contract.Fill` 喂给现有账本 `ledger.ApplyFill`，持仓状态机/金字塔/止损上移/
两亏拉黑/恒等式审计**全部复用**，规则零重写。

这是历史校准链（walk-forward）的第一块多米诺：没有它，M8.3 体制运行器、M8.4 参数扫描、
以及「用 36 年历史提前校规则参数」全部无法启动。

**定位边界**（docs/01 §9）：只做引擎验证，不是回测产品；观察期内只产出「问题清单 + 分体制
证据」，不改规则。

## 2. 现有链路复盘（为什么撮合器这么薄）

生产链路（ADR-4 人工成交录入）：

```
signal(信号) → planner(六问→plan_order) → 人看计划 → 挂单 → 成交后贴单
                                              ↓
                              ledger.ParseFill(解析文本) → ledger.ApplyFill(成交入账)
```

`ledger.ApplyFill`（ledger.go:301）已经完整实现了：
- 幂等检查（FillExists）
- 订单匹配（PendingOrdersFor 取最接近 limit 的 pending 单）→ 状态机 pending/placed → filled
- 买入 → 开仓 / 加码（金字塔腿 + 止损上移，只升不降）
- 卖出 → 减仓 / 清仓（ClosePosition 落 realized_pnl + B2 两亏拉黑 + watch 出池）
- B2 接线（watch watching/pending → holding → exited/blacklisted）

**M8.2 唯一要补的**：把「人贴单」替换成「模拟器产单」。撮合器只做一件事——
给定 `plan_order` + 当日 `daily_bar`，判定是否成交、以什么价成交、算多少费用，
产出 `contract.Fill`，然后原样调用 `ledger.ApplyFill`。其余状态机一字不动。

## 3. 撮合成交语义（核心）

### 3.1 输入

- **订单**：`plan_order` 中 `status IN ('pending','placed')` 且 `execute_date == 当日` 的行
  （execute_date 由 planner 按 sh000001 日历推得 = 信号日的下一交易日）。
- **行情**：当日 OHLC（`daily_bar`）+ 昨日收盘（涨跌停判定用，`BarsWindow(code, date, 2)`）。

### 3.2 触发判定（停损单，上穿/下穿）

设触发价 `T = trigger_price`，当日 OHLC 为 O/H/L/C：

| 单类 | 触发条件 | 成交价 |
|------|----------|--------|
| stop_buy（买入） | `O >= T`（跳空高开越过）| **O**（更差价格，市价成交）|
| stop_buy | `H >= T` 且 `O < T`（盘中上穿）| **T** |
| stop_buy | 否则 | 不触发，订单留待次日 planner 过期 |
| stop_sell（卖出）| `O <= T`（跳空低开跌破）| **O** |
| stop_sell | `L <= T` 且 `O > T`（盘中下穿）| **T** |
| stop_sell | 否则 | 不触发 |

> 注：当前 planner 里 `limit_price == trigger_price`（planner.go:293 / 313），两字段相等。
> 撮合「成交价」取 `limit_price`（跳空时取 O）；若未来两者不同（滑点委托），成交价仍按
> limit_price 走。触发判定**只用 trigger_price**。

### 3.3 涨跌停约束（简化版，初版）

A股涨跌停时单子成交受限。**初版用简化判定**（只挡「一字板」，不逐笔模拟排队）：

- 一字板判定：`H == L`（当日单一价格），再按方向区分涨停/跌停。
- **一字涨停**：买入单**跳过**（封死买不进）；卖出单**正常成交**（封涨停时卖单优先成交）。
- **一字跌停**：卖出单**跳过**（封死卖不出）；买入单**正常成交**。
- 非一字板（盘中触及但收盘打开）：按 3.2 普通触发处理，不额外挡。

**待拍板/后续增强**（§8）：涨停价的精确计算需 `security.board`（main ±10% / gem,star ±20% /
ST ±5%）+ 制度日期（创业板 2020-08-24、科创板 2019-07-22 起 20%），初版不引入，先用
「H==L 即一字板」近似，够挡最恶劣的假成交。

### 3.4 T+1 约束

当日买入的仓位当日不可卖。**撮合顺序 = 先卖后买**（先处理卖出释放持仓，再处理买入），
且卖出单的 `qty` 在 plan 生成时已锁定为「昨日持仓量」，天然不含当日买入 → T+1 满足。

防御规则：同日同股同时有 buy 与 sell 单（规则上几乎不可能：breakout/pyramid 与 stop/failed
互斥），按**先卖后买**处理并打一条 warning 日志，不硬报错。

### 3.5 整手

`qty` 已由 planner 按 100 股整手生成（planner.go:261），撮合器不二次取整。

### 3.6 费用（A股摩擦）

新增参数（§6.1 迁移 0006），初版用**当前费率常数**，可配：

| 参数 | 默认 | 说明 |
|------|------|------|
| `fee.commission_rate` | 0.00025 | 佣金万2.5，双向 |
| `fee.commission_min` | 5 | 单笔最低佣金（元）|
| `fee.stamp_tax` | 0.001 | 印花税千1，**卖出单边** |
| `fee.transfer_rate` | 0.00001 | 过户费万0.1，双向（简化，沪深同率）|

```
buy  fee = max(price×qty×commission_rate, commission_min) + price×qty×transfer_rate
sell fee = max(price×qty×commission_rate, commission_min) + price×qty×stamp_tax + price×qty×transfer_rate
```

> 历史费率变化（印花税 2008-09-19 起单边千1，此前双边；佣金多年下调）列为已知偏差（§8），
> 初版不按时间段切费率；费率全走 param 可配，校准时可临时覆盖。

### 3.7 订单有效期（单日有效）

达瓦斯停损单「明日有效」：订单在其 `execute_date` 当日撮合；当日未触发 →
次日 planner 的 `ExpireStaleOrders`（repo_trade.go:289）自动置 `expired`。
信号是「首次事件」不重发 → 未成交的止损单不再补。这是**设计好的语义**（§8 记录
「信号发出但订单未成交」比例，作为 `sell.discount` 校准依据）。

### 3.8 复权日处理（不复权方案 · 用户拍板 2026-10-19）

用户拍板：**不复权原始价 + 复权日清仓**。不篡改历史数据，把复权日当作交易事件处理。
已核实数据源：TDX `T0002/hq_cache/gbbq`（194015 条股本变迁记录，6444 股，1990~2026，
pytdx GbbqReader 可解析）；初版**不引入 gbbq**，改用跳空检测（同源零依赖）。

**复权日识别（跳空检测）**：某股当日 `close` 相对昨收跌幅超过该股涨跌停限制 + ε 余量
（主板 9%、创业板/科创板 19%、ST 4.5%）→ 判定为除权跳空日。正常交易不可能单日跌超
涨跌停，故超限即除权（一字跌停恰好 ≈ 涨跌停，不误判）。跳空日集合在回放引导阶段预计算。

> **数据源调研（2026-10-19）**：精确识别除权日的更优来源已锁定——Go 开源库
> **abulo/tdx**（github.com/abulo/tdx）已实现 gbbq 解析 + 复权因子（仿射变换
> `QFQMul×price + QFQAdd`，四舍五入到分，与通达信桌面端逐日对齐），可直接参考/移植。
> 本地 gbbq（H:\new_tdx64\T0002\hq_cache\gbbq，194015 条事件）零联网、数据已在本地。
> 云数据源（baostock 免费但有 IP 限制+T+1 延迟；tdxquant 官方权威但需客户端 TQ 或积分）
> 均需 Python 运行时，与「纯 Go 单 exe」架构冲突（docs/01 §9），当前不引入。
> 精确 gbbq 解析列为 M8.2.1 增强；初版跳空检测足够。

**复权日处理（两条）**：
1. **持仓股**：跳空日当天撮合器最前强制清仓——生成 `sell` fill（价格=前一日收盘，
   `reason="dividend"`），避开跳空损失。清仓后该股**全部在途订单**（含 execute_date 更晚的
   止损卖单/突破买单）通过 `CancelOpenOrders` 标记 `cancelled`（初版只跳过当日单，
   2018-05-23 sz300630 次日陈旧止损单触发「卖出无持仓」暴露，已修）。
2. **watch 股（未持仓）**：不额外处理。跳空日 signal 会因「今收<下轨」自然出池，复权后
   价格稳定重新入池、箱体基于新价重算——属**可接受行为**，不算污染。

> 待细化：若校准阶段发现跳空日假 stop 信号过多，再上「跳空日跳过 boxscan/signal 判定」
> （M8.2.1）。初版先记录「跳空日信号/出池」计数，用数据决定要不要加。

## 4. 与 ledger 的接口（复用，零改动）

```
撮合器 Match(day):
  orders = TradeRepo.PendingOrdersForExecuteDate(day)   // 新查询，见 §6.2
  for o in orders (先 sell 后 buy):
    bar, prev_close = BarRepo.BarsWindow(o.code, day, 2)
    if 一字板挡住方向:  continue
    px, hit = 判定触发(§3.2)
    if !hit: continue
    fee = 算费(§3.6)
    fill = contract.Fill{PlanOrderID:o.ID, Code:o.code, Date:day, Side:o.side,
                         Price:px, Qty:o.qty, Fee:fee, RawText:"sim:"+...}
    ledger.ApplyFill(fill)        // 状态机全复用，含幂等/订单filled/持仓/腿/拉黑/出池
  ledger.Snapshot(ctx, day)       // 覆盖当日权益快照（见 §5 时序）
```

**关键复用点**（不改 ledger 一行）：
- `ApplyFill` 里 `PendingOrdersFor(code, side, date)` 会把 fill 关联到 plan_order 并置 filled，
  与 §4 新查询 `PendingOrdersForExecuteDate` 相互独立、不冲突。
- 开仓/加码的腿号、止损上移、B2 接线、两亏拉黑全部由 `ApplyFill` 现成逻辑承担。

## 5. 接入回放循环（时序）

M8.1 的 `Replay`（backtest.go:372）目前六任务链 = `boxscan→screen→poolsync→signal→plan→report`。
M8.2 把撮合插到 **plan 之后、report 之前**：

```
每日 D 循环：
  boxscan → screen → poolsync → signal → plan → 【match 撮合 execute_date==D 的订单】
    → 【ledger.Snapshot(D) 覆盖】 → report
```

**为什么这个顺序**（时序关键，易错）：
1. `plan` 在 D 日会：(a) 生成 execute_date=D+1 的订单；(b) `ExpireStaleOrders(D)` 清掉
   execute_date < D 的旧单；(c) 末尾 `Snapshot(D)`。
2. 撮合在 plan 之后跑，撮合 execute_date == D 的订单（这些是 D-1 日生成的），产生当日 fills。
3. **必须撮合后再 `Snapshot(D)` 覆盖**——否则 D 日权益快照不含当日成交，权益曲线漏当日。
   `Snapshot` 幂等（UpsertEquity ON CONFLICT DO UPDATE），重算覆盖安全。
4. `report` 最后跑，日报能反映当日成交。

**不写 daily_run**：match 不是生产任务，不进 sixTasks 数组、不占 daily_run 心跳位、不参与
M8.1 的 as-of 差分 dump（Compare 里 daily_run 是比对项，match 的产出通过 fill/position/
equity_snapshot 三张表体现）。

## 7. 验收口径

1. **单元测试**（`internal/match`）：
   - 上穿/下穿/跳空三种触发价的成交价正确性（手算用例）。
   - 一字涨停挡买、一字跌停挡卖。
   - 费用计算（买/卖、最低佣金 5 元边界）。
   - 先卖后买顺序。
2. **恒等式审计**：撮合结果跑 `ledger.AuditEquation`，权益恒等式 + 持仓闭合 + 订单闭合全过。
3. **差分审计不回归**：M8.1 的 `--mode verify`（progressive vs prefill）在加入 match 后
   仍须全等——match 同样只用「当日及之前」的 K 线，不能偷读未来。
4. **已知案例手算**：拿 20 日 verify 里已出现的信号（09-17 sz300739 / 09-21 sz300473），
   手算其 execute_date 的 OHLC 是否触发、成交价，与撮合器输出逐字段对账。

## 9. 明确不做（本期）
