## 1. 对 WorkBuddy + DeepSeek 工作的评价

结论：**WorkBuddy + DeepSeek 已把 Darvas-box 从想法推进成了有工程骨架、有实验账本、有可复核历史证据的规则交易工具。**这是本项目最重要的阶段性成果。

### 1.1 已经做成的事情

- 建立了单一理论边界：`docs/00-darvas-theory.md` 作为理论宪法，明确不把其他交易理论偷偷混入系统。
- 完成了 Go + SQLite + 本地 HTTP GUI 的可运行架构，以及 ingest、boxscan、screen、poolsync、signal、plan、report、backtest 等链路。
- 把六问落到了可执行产物：买什么、何时买、买多少、卖什么、何时卖、卖多少。
- 建立了实验分层：A 类分带统计、B 类规则回测、固定基线、代表年份、剔除前三、复利账与样本外纪律。
- 已经完成多项关键实验：距 52 周新高、箱体高度、MA60 闸门、仓位语义、浮盈回吐、`staledays`、突破强度/量比，以及 A0/A1 箱体轨迹工程验证。
- 能够识别并记录“没有 edge”“结果不稳定”“不能挑单点最优”等负结论。这比只收集盈利结果更重要。
- 已经把多个死参数、错误口径、基线混用和报告之间的冲突登记出来，形成了可审计的研究资产。

### 1.2 为什么这项工作能走到现在

这不是单一模型“聪明”造成的结果，而是协作机制产生的结果：

- WorkBuddy 提供了持续读写仓库、运行脚本、维护记忆和串联长周期任务的工程执行能力。
- DeepSeek 在大量文档、实验记录、代码和历史上下文之间保持了较强的整理、归纳和推进能力。
- 用户持续拍板理论边界、参数取舍、实验顺序和“不允许偷偷改变规则”等关键决策。
- GPT 本轮主要承担独立审计：交叉核对代码与文档、识别报告互相矛盾的事实、区分“参数存在”与“参数已验证”、统计剩余实验，并将风险写成可交接的整改事项。

因此，合理评价不是“哪个模型赢了”，而是：**WorkBuddy 的持续工程循环 + DeepSeek 的文档和实验推进 + 用户的决策纪律 + GPT 的独立复核，形成了互补系统。**全用某一个模型，确实更容易把局部正确误写成系统完成，或在长上下文中遗漏反例。

## 2. 当前状态：已经接近完结，但还不是“全部验证完成”

当前系统可以作为**人工辅助决策工具**，但不能宣称已经证明未来有稳定优势。

已经具备：

- 规则交易引擎和日常流水线骨架。
- 历史回测、实验报告和参数账本。
- 计划器输出买卖触发价、数量和全仓卖出计划。
- 可解释的部分箱体、仓位和出场研究结论。

仍未闭合：

- 买入端剩余 Box 定义和升势定义证据。
- `raiseStops` 箱体止损上移是否及时、是否保护大赢家的事件研究。
- 生产对象链：`signal → plan_order → fill → position` 的显式关联和 `reason_json.box_id` 完整性。
- 实盘成交命中率、漏单成本、实际滑点、停牌/涨跌停等执行证据。
- GUI 测试失败的根因。
- 2019 年以后冻结样本外考试。

14 年新基线的 CAGR、MDD 和终值只能说明：在特定历史数据、复权、撮合、仓位和参数下，系统重放得到了一条历史资金曲线；不能直接推导未来收益。

## 3. 最后冲刺的实验清单

### 3.1 必须做的 5 个实验包

以 `docs/29-box-gradient-experiment-plan.md` 为唯一实验事实源，当前必须队列是：

1. **止损随 Box 上移事件研究**
   - 研究 `raiseStops` 实际触发次数、上移幅度、上移滞后天数。
   - 按 `0 / 1–3 / 4–10 / >10 / 从未上移` 分带。
   - 必须报告净利、每单位净利、胜率、PF、MFE、回吐金额、回吐率、剔除前三结果。
   - 若差异超过噪声且大滞后带更差，才进入 B 类规则验证；若差异在噪声内，关闭该问题，不凭直觉改止损。

2. **入场/池管理旋钮扫描**（一个 A 类打包实验，内部 5 个旋钮）
   - `pool.min_watch_days`
   - `screen.latedays`
   - `pool.flatboxmax`
   - `match.max_entry_gap`
   - `regime.a.lookback` / A 判据相关口径
   - 只做同库分带和固定口径统计；不得把不同参数库的分带结果直接当成端到端优劣。

3. **P3-8：升势 / 最高 Box**
   - 先冻结定义，再做事件研究。
   - “升势”可候选 MA20>MA60 或箱体中枢递增，但必须先由用户拍板，不得让实验结果反向偷偷定义理论。
   - “最高 Box”必须改用 Box 序列历史定义，不能继续使用已知 0 命中的 `box_top ≥ 52 周高点×0.999` 代理。

4. **P3-7：Box 宽度窗口**
   - 验证 3 / 5 / 10 / 20 / 60 日窗口。
   - 这是最昂贵、最可能改变 Box 身份和全链路语义的实验，必须最后执行，固定新基线和数据口径。
   - 不能只比较某一年的总收益；必须按固定四项口径、逐年稳定性、剔除前三、样本量和最差年判定。

5. **`box.min_width=5%` 参数化验证**
   - 验证 0.03 / 0.05 / 0.08 / 0.10 等档位。
   - 明确这是工程噪声过滤假设，不是原书规则。
   - 结果若只是某一档历史最优，不得直接改生产默认；必须检查跨年稳定性和剔除前三后的符号。

### 3.2 必须队列之外的收尾

- **LB-3、LB-6**：Box 生命体征的剩余部分，按 `docs/29` 的前置条件决定是否补做。LB-1、LB-2、LB-4、LB-5 已有结论，不能重复包装成“十一维全部未做”。
- **2019+ 样本外考试**：不是普通实验，必须在规则、参数和实现冻结后唯一执行。任何提前查看或据此调参都会使期末考失效。

### 3.3 暂不自动启动的可选研究

以下项目当前不是必须队列，不得在最后冲刺中擅自插队：

- 大赢家加仓放大。
- “牛冲熊守”动态仓位。
- `P2-6b trail%` 梯度。
- `sell.discount` 专项梯度。
- `docs/35` 的 pinbar / “量=分歧”第二买点。

特别是 `sell.discount=0.97`：当前确认的是“参数已参数化、默认值存在”，不是“0.97 已证明最优”。若用户正式立项，必须另写预注册方案，区分初始止损与移动止损，不能拿 trail% 研究代替。

## 4. 实验执行纪律

每一项实验都必须：

1. 写清问题、假设、变量、固定参数、样本区间和停止条件。
2. 固定唯一基线：新基线单镜上证、`max_hold=14`、`equity_gate=off` 及其余活参数必须明确记录。
3. A 类分带和 B 类端到端回测分开，不混用结论。
4. 先看样本量，再看净利；`n<30` 不下结论，regime 类还要看有效段数。
5. 必报总账、已实现净利、权益变动、CAGR、MDD、PF、胜率、最差年、逐年符号、剔除前三和集中度。
6. 不挑单点最优；发现非单调、断裂点或由少数赢家支撑，必须如实登记。
7. 代码、参数、数据库、报告和结论必须一一对应；没有报告、数据和运行收据的“完成”不算完成。
8. 任何研究脚本绕过生产生命周期缺口时，必须明确标注“近似研究”，不能升级为生产链路已完整。
9. 2019+ 在规则冻结前保持干净，禁止用于调参。
10. 实验失败、无 edge、被噪声吞没和停止执行，都是正式结果，必须写入实验账本。

## 5. 最后冲刺的工程查漏补缺

### P0：不处理就不能声称完成

- 修复或定位 `internal/gui.TestAPIEndpoints` 的连接失败。
- 对生产配置、迁移种子、回测注入做一次单一事实源对账，重点核对 `max_hold`、`equity_gate`、MA60 gate、`box.max_growth_days`。
- 恢复 `signal → plan_order → fill → position` 的显式可追溯链；至少保证 `reason_json.box_id`、signal ID、order ID、position ID 能互相核对。
- 对 stop、failed breakout、保护性 stop、time stop、复权清仓、人工卖出做出口分解，避免只看一个 `close_reason`。

### P1：应在样本外考试前完成

- 完成止损上移事件研究并决定是否进入 B 类。
- 把 Box 身份、出生日期、确认日期、突破日期、死亡/破坏日期的生命周期边界写清楚。
- 核对 `docs/03-erd.md` 的 schema 版本注记与实际 migrations。
- 清理 `TrackLevel` 等已退役参数和注释中的 winner 旧语义，避免文档与代码再次漂移。
- 完成计划器、报告器和 GUI 的 reason 字段契约，避免 JSON 字符串成为唯一隐式接口。

### P2：实盘观察阶段补齐

- 记录计划到成交的命中率和漏单成本。
- 记录实际滑点、涨跌停、停牌、复权清仓和人工介入。
- 运行 GUI smoke 和完整 `darvas serve` 人工流程。
- 以极小资金或模拟盘做执行质量观察，不把观察结果倒灌成历史参数优化。
