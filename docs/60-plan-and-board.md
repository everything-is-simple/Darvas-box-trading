### 7.1 中断了怎么续（**不丢一天**）

带 `--set` 的臂**首次起跑**不能续跑参数，但**续跑本身完全可用**——关键是续跑时**不带 `--set`**：
库内 `param` 已固化档4=0，`baseline.param_fingerprint` 即按它计算，不带 `--set` → 指纹自洽 →
`resumeRegime` 通过身份校验，从「六任务全 ok 的最大日期」之后继续。

```bash
# 中断后：一条命令续上（不要加 --set）
python scripts/base_run.py --cont --src var/bt/full_hist_adj.db \
  --exe bin/darvas-dev.exe --db var/bt/arms/bt_a1_t4off.db --resume
```

证据（2026-11-05 20:19 演练，10 日小库）：`[bt] resume: 基线身份一致（…-v1），断点 2005-01-14，续跑 11 个交易日后段`，
续跑后档4 仍为 `0`（未被命令行 COMMON 的 0.5 覆盖）。
**唯一不可恢复的情况**：库文件本身被删或损坏 → 才需从 2005 重跑。

> 为什么不用「分年库」：单年库每年重置初始资金，年际不连续，仓位约束与连续账本不同，A1 就无法与基线
> `+415,431` 对比（连续库已替代「单年库 + 事后链式复利」，见 `53 §10`）。抗中断靠 `--resume`，不靠拆库。
