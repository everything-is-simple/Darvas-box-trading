## 2. 三道防线

### 防线一：命名强制对齐（静态检查，`go vet`自定义或脚本）

`scripts/check_consistency.py`（CI/提交前跑）：

1. **枚举对齐**：抽取contract.go中的`BoxStatus/WatchStage/SignalType/OrderStatus`常量集合，与DDL的`CHECK(...IN(...))`集合做差集比较 → 不一致即失败
2. **表覆盖**：解析DDL的CREATE TABLE列表 vs 03-erd.md的Mermaid实体列表 → 缺一即失败
3. **任务ID对齐**：scheduler常量表 vs 01文档§4任务ID列表
4. **参数键对齐**：param 种子键集合 ⊆ 01文档§6参数表键集合
   - ⚠️ **2026-10-28 修正口径**：对齐目标是「种子键 ⊇ 代码实际读取键」；**死参数（代码不读）应从
     docs/01 §6 移除、从种子清理**，而非保留凑数。当前已清出 28 真死键（`risk.*` 加码 / `pos.units.*`
     旧单位 / `regime.mult.*` 牛熊乘数等），见 docs/01 §6.1。
   - ⚠️ **2026-11-03 修 bug**：旧实现只认 `INSERT OR IGNORE`，漏掉 0018 的裸 `INSERT` 与 0025/0026 的
     `ON CONFLICT DO UPDATE`——「26 键」这个数字错了两个月，真值 40。现改为与 C6 共用
     `scripts/param_ledger.py` 的统一解析（四种写法全吃）。
5. **参数台账对齐（C6，2026-11-03 新增）**：`docs/44` 生成区台账 == 「代码实读键 + 迁移演化后的生效值」。
   这是唯一回答「基线到底包含哪些参数、值是多少」的机器判据。
   - 漂移时唯一修法：`python scripts/param_ledger.py --write`（改代码/migration 之后），**禁止手改表**。
   - 键集来源 = `GetFloat/GetInt/GetString` 的字符串字面量，因此**新增参数只要写了代码就会被要求登记**，
     人力维护的表不可能再漏。
6. **数字对账（C8，2026-11-06 新增）**：文档里的收官数字必须等于账本算出来的（详见 §9）。
   链：账本 DB → `docs/anchors/ledger_anchors.json`（快照）→ `55 §11.10` 生成区 → 归档 `48`／`60`（2026-11-09 整份归档）／`README` 引用；
   C8 的 `CROSS_DOCS` 仍扫归档稿，防历史稿数字被手改而不报错。
   - 漂移时唯一修法：`python scripts/doc_anchors.py --write`，**禁止手改锚点表或快照**。
7. **死链检查（C9，2026-11-06 新增）**：现役 `docs/*.md` 的 md 链接、反引号路径、`NN §x` 章节引用必须可达。
   - 为什么必须机检：改名、归档、重编号都不会报错，只会让引用**静默指向不存在的节**。
   - 归档稿与实验报告（`docs/archive/`、`docs/experiments/`）冻结不检：它们保留历史编号，
     且报告由脚本重生成（禁手改），对它们查「今天的路径」只会产生噪声。

### 防线二：Schema漂移检测（运行时）

- store.Open时执行migrations后，做`schema_version`表校验
- `darvas doctor`子命令：dump实际schema与migrations累积结果对比（复用tradebuddy的schema-dump思路）
- 备份恢复演练时必跑doctor

### 防线三：流程卡点（变更协议）

**任何PR/commit必须二选一：**

- ✅ 声明「不涉及契约」（改动仅在模块内部实现）
- ✅ 附带「契约变更」：同一commit内包含
  1. migrations新增`000N_xxx.sql`（**禁止修改已发布迁移**，只允许append）
  2. docs/03或04的对应更新
  3. 若涉及状态枚举：ERD状态机表新增迁移行
  4. 跑`check_consistency.py`通过

commit message约定：`feat(box): ...` / `feat(contract): ...`（contract前缀的commit=契约变更，评审必看文档diff）。

### 3.2 接口一致性（编译期）

- 模块构造函数签名统一：`NewXxx(deps...) Xxx`，deps全部是contract接口类型 → **mock天然可行，测试不碰真DB**

### 3.3 行为一致性（理论与代码）

每个领域判定规则在代码注释中**必须引用理论条目号**，例如：

```go
// 突破日成交量 ≥ 50日均量 × VolMultiplier，无量突破=假信号
```

`scripts/check_theory_refs.py`：抽取代码中的`§`引用，核对00文档章节存在性（防文档重构后悬空引用）。

## 7. 统计口径一致性（2026-10-27 立项，C5）

> 复利口径引入后，同一批回测可以算出两套数字（加法账 / 复利账）。口径混用比算错更危险，故立为检查项。

### 7.1 双口径定义（不可混用）

| 口径 | 定义 | 用途 |
|---|---|---|
| **加法账** | Σ 各年 `pnl`（已实现净利） | 与历史总账对账、逐年比较（+842,801 为 raw 时代旧值已作废；现行 adj 口径 +1,213,822，见 55 §11） |
| **复利账** | 逐年链式复利终值（`total_d/total_{d-1}`） | 真实资金曲线、CAGR、最大回撤、擂台判据 |

- `e17_metrics.csv` 的 `ret` 是**权益口径**、`pnl` 是**已实现口径**，V 型年（2009）二者背离；
  任何「亏损年/盈利年」的判定必须以 `pnl` 为分类、以 `ret` 为描述，两者不得互相替代。
- 报告若同时给两口径，必须显式标注表头（「加法账」「复利账」），禁止裸写「净利」。

### 7.2 C5 机检三条（`scripts/e17_snowball.py` 与任何统计脚本必须满足）

1. **Σ 年净利 = `metrics.pnl` 之和**（逐库比对，容差 1e-6）；
2. **逐年复利因子 = 该库年末权益 / 1,000,000**（容差 1e-6）；
3. **逐年交易日数之和 = `metrics.days` 之和**。

任一条不过 → 该脚本产物不得入库，报告不得引用。

### 7.3 复盘纪律

- 每当统计脚本口径发生修正（如 2026-10-27 的 stop 2010 勘误：已实现 −14,884 曾被误报 +3,012），
  必须在报告中保留「勘误段」并同步修正所有引用它的文档；**不允许静默改正**。
- 已发布数字若被修正，须在 commit message 中写明旧值、新值、影响范围。

### 8.1 判据窗口纪律（Q4：2019+ 不解冻）

- 判据计算窗口锁定 **2005-01-01 — 2018-12-31**。参数在 2005–2018 上选定，样本外不得参与选参。

- 注释里的决策日期（如「2026-11-03 定案」）**不参与检查**——只认代码字面量，避免噪声。

### 8.2 口径横幅（Q1：旧结论加横幅保留）

- 一切读取 raw（不复权）库**个股价格或交易账本**的报告，必须在标题下带「已作废」横幅。

## 9. 数字对账（C8）与死链检查（C9）（2026-11-06 立项）

> 起因是「文档的正确性能不能验收」这个问题。原有机检（C1–C4、C6、C7 共 7 项；编号 C5 留空未实现）覆盖的是**代码 ↔ 文档的契约面**（枚举/表/参数/时刻），
> 但有两个面完全空白，且都是「坏了不报错」型：
> ① **文档里的数字 vs 账本算的数字**——手抄、重跑、改口径都会分叉；
> ② **文档之间的导航**——改名、归档、重编号会让 `55 §11.9` 指向一个不存在的节。
>
> 机检项数以 `scripts/check_consistency.py` 实现为准（现行共 8 项：C1–C4、C6–C9）。

### 9.1 C8：四段链路，缺一段就有数字失真

| 段 | 检查 | 失败含义 | 修法 |
|---|---|---|---|
| ① 文档 ↔ 快照 | `docs/55 §11.10` 生成区 == `docs/anchors/ledger_anchors.json` | 有人手改了锚点表 | `python scripts/doc_anchors.py --write` |
| ② 快照 ↔ 账本 | 快照 == 从账本重算（含引擎 sha256 一致性） | 账本重跑过 / 快照过期 / 换了引擎 | 同上（重算后覆盖快照） |
| ③ 跨文档引用 | `64`／`README`／`29` 与 3 份归档稿（`48`／`60`／`53`，见 `doc_anchors.py` 的 `CROSS_DOCS`）里「引基线收官数字」的句子，每个金额/百分比/倍数必须**在册** | 手抄错一位数，或口径改了口号没改 | 改文档，或把新数字登记为锚点 |
| ④ 全库近似值 | 现役 `docs/*.md` 全部数字：**不在册** + 与某锚点**同形状** + 相对差 ≤0.1% | 手抄错末几位（在册 `+1,213,822` 的末三位被改掉） | 改回在册值；真是新口径则重跑账本 `--write` |

- **锚点唯一事实源** = 账本（`var/bt/base/bt_baseA_cont_adj.db`），快照只是它的可 diff 存证。
- **锚点分两级（共 65 键）**：
  **一级·收官（29 键）** 总账 / 概率 / 四档 / 判据；
  **二级·过程（36 键，2026-11-06 增）** 持有天数五档（≤2 / 3–5 / 6–10 / 11–20 / >20，各 n·Σpnl·占比·胜率）、
  四档各自的每单位收益（档1/档2 补齐，此前只有档3/档4）、
  出口四类（stop / stop_box / time_stop / failed_breakout，各 n·Σpnl）、集中度尾部（偏度、前 1%/5% 贡献、
  剔前 10、最长连亏 n·金额）。加它们的理由：`64` 总典（人类第一入口）整表抄了三张过程分解表，
  实测 77 个数字里 61 个不在册——账本一重跑就静默过期，而读者只看 `64`。
  唯一仍无生成区的是「首次转正日分带」（需逐日 mark，账本未存），`64 §2.2b` 已注明只能人工复算。
- 「在册」的判定只认三类形状：带千分位的金额、带小数的百分比、`×倍数`。章号（`55 §11.9`）、档号（剔前3）、年份不参与，避免噪声。
- ③ 的**触发面**只认承载收官锚点的节：`55 §11` 整章 / §11.2 账本 / §11.3 概率 / §11.9 判据 / §11.10 台账。
  §11.5（亏损分解）、§11.7（加仓）引的是过程数字（如 time_stop 累计亏损 815 笔），**不算收官锚点**——
  早期版本用裸 `55 §11` 前缀，把这些行也扫进来，导致假警。
- 库不在时（CI/换机器）：② 段跳过并**明确打印**「只校了文档↔快照」，不静默通过。
- 白名单 `EXTRA_OK` 目前只有一项：判据 5 的 MDD 容忍线 `−33.50%`（基线 −32.50% + 1.0pp）。加白名单必须写理由。
- **④ 为什么必须有**：③ 只扫「明确在引基线数字」的句子，而 `55` **正文自己就抄了 5 份副本**
  （§0 状态行、§11.2 摘要、§11.3 表、§11.9 判据、§13），③ 看不见，肉眼也极难发现。
  实测：把 §11.3 合计的末三位改掉，③ 仍全绿、④ 立刻命中并指出「≈锚点 net_pnl」。
- **④ 的两个约束缺一不可**（否则噪声爆炸，实测 0.5% 阈值 12 条全是误报）：
  **同形状**（千分位/整数位数/小数位数都相同）挡掉 `14.0%` vs 14.0 年、`18.56%` vs 18.60%；
  **0.1%** 挡掉子样本数字 `1,059` vs 均笔 `1,063`（差 0.38%）。金额 7 位时 0.1% ≈ 1000 元，正好是「末三位抄错」量级。
- **④ 只查「像金额的大数」**（带千分位或 ≥1 万）。小额无量纲值必然撞：`skew = 8.06` 与旧口径
  `CAGR 8.06%` 形状数值全同，无法区分（实测假警 2 处）。代价：8.06 / 113.7% 这类小数值抄错抓不到，
  只能靠 ③（它们出现在带「基线/§11」关键词的行时仍受精确值约束）。
- **`--write` 幂等**：内容没变就复用旧 `generated_at`，不制造纯时间戳 diff（否则每次 `--write` 都弄脏两份文件，
  真正的内容变化被淹没）。手改过生成区时仍会被重写覆盖。
