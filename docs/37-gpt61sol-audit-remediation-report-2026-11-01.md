## 0. 结论先行

Darvas-box 已经是一个**可运行的规则交易工具**，不是一个已经证明具有稳定未来优势的完整交易系统。

更准确的状态：

- **算法骨架已成形**：箱体状态机、信号、计划、撮合、持仓、账本、报告和回测链路均已实现。
- **六问的“生成能力”基本具备**：系统能够生成候选、买卖触发价、数量和全仓卖出计划。
- **六问的“证据能力”不对称**：买入位置、部分仓位规则和若干箱体体征有历史实验；卖出价格折价、初选器、箱体定义宽度、升势/最高箱体等仍未充分验证。
- **最重要的风险不是单个 0.97 参数，而是“决策链可追溯性、样本外验证、执行现实性”尚未闭合**。
- **当前不能把 14 年回测的 CAGR、MDD 或“已验证参数”直接表述为未来可复制收益**。数据存在幸存者偏差、前复权影响、成交与流动性简化、年末浮盈混入权益口径等已登记限制。

## 2. 六问端到端审计

### 2.1 “买什么”

**实现：基本具备；验证：不完整。**

当前路径：

```text
全市场日线 → boxscan → screener 四条件 → candidate 快照
→ pool watch 状态 → breakout signal → buy plan_order
```

已确认的事实：

- `screener` 实现流动性、RS 超额收益、放量比下限和箱体形态门槛。
- 箱体形态是候选硬门槛，其余条件主要用于评分；这意味着“买什么”并非四条件全部必须同时通过。
- RS 使用“个股收益−上证收益”的超额收益口径，旧比值法已退役。
- `box.max_growth_days` 已接入买入准入，但 B 类实验尚未完成。
- `pos.newhigh_ladder` 的距 52 周高分档规则已进入计划器，但其是否改善端到端账户仍需和新基线严格区分。

主要问题：

- `screen.rs_excess_min=0.20`、`screen.turnover=50M`、`screen` 放量下限 `2.0` 未完成系统性的 OFAT 端到端验证。
- 文档曾描述量比上限 `[2,5]`，代码没有上限；这会影响候选池数量、实验复现和用户理解。
- “箱体形态 confirmed 或刚 broken_up”与“后续 signal 只消费 broken_up 事件”之间存在语义层次差异，需明确候选是观察池筛选，不是可买信号。
- “买什么”目前强依赖历史存续股票池；2005–2018 的退市股、历史 ST 状态和当时可交易性没有完整时点重建。

**评级：B-。**

### 2.2 “何时买”

**实现：较完整；验证：仅限历史口径。**

已确认：

- 箱体上破由 `close > top × buy.premium`、前 50 日均量放量和非一字板组成。
- 信号采用首次事件语义，重跑具有幂等保护。
- 计划执行日区分 T 日生成和 T+1 执行日，日历优先使用上证日线。
- P1-4 对已有成交样本的强度/量比分带进行了 A 类分析；量比低端又做了 B 类四代表年扫描，结论是“市况相关”，不能简单固化成一个普遍最优门槛。

风险：

- A 类成交样本被现有 `buy.premium` 和 `match.max_entry_gap` 截断，0–3% 强度区间结构性无样本；因此“3% 已验证最优”是错误表述。最多能说：在当前门槛产生的可成交样本中，没有发现门槛之上的稳定单调优势。
- B 类量比结果只覆盖代表年，不是 14 年全样本；1.5 的优势被 2015 牛市显著贡献，不能称为固定生产规则已证明。
- `failed_breakout` 使用自然日 `withinDays`，而大部分系统规则使用交易日计数；周末/长假可能造成边界不一致。该差异应明确为规则选择或修正为交易日语义。
- `signal` 与 `plan_order` 没有 source signal 外键，信号到计划到成交的链路审计依赖 JSON 和时间/代码匹配。

**评级：B-。**

### 2.3 “买多少”

**实现：具备；验证：仓位语义有混用风险。**

已确认：

- 1 单位默认是权益的 2%，并做 A 股整手取整。
- 距 52 周高分档可决定 3/2/1/0.5 单位；同股持仓期间不加码。
- MA60 stop 闸门和 max_hold=14 的新基线均有回测证据，但证据来自特定回测参数集。
- 代码仍保留 `equityBudget` 逻辑，且 `pos.equity_gate=on` 时会按总仓位和单票上限裁剪数量；关闭时则不生效。

关键问题：

- “A M1 2/1 单位”和“newhigh ladder 3/2/1/0.5”不是同一套仓位语义；代码在 ladder 开启时优先使用 ladder，文档必须明确这是替代关系，而非叠加关系。
- `max_hold=14`、`equity_gate=off` 是新基线回测语义，不应未经生产配置核对就称为全系统默认。
- 单位数、挂单占用、持仓市值和整手截断会共同改变资金轨迹；不能仅用每单位净利替代账户级结果。
- 计划器在组合约束下可能拒单或缩量；“买多少”必须同时输出原始单位、实际股数、缩量原因和账户占用。

**评级：B-。**

### 2.4 “卖什么”

**实现：规则存在；实体边界和审计不足。**

当前卖出对象主要是有持仓且发生 stop/failed breakout/time stop 等出口条件的 position。`Box broken_down` 本身不等于 position 已平仓，这一点在 docs/36 中已写清楚。

缺口：

- 最新箱体、触发箱体、入场箱体和持仓当前止损之间的关联不够强，`entry_box_id` 全 NULL 是直接证据。
- `box` 的状态投影会被重算，不能把当前表行当作不可变历史事件。
- 计划的 `reason_json` 虽含箱体上下轨和触发价，但不是强外键，且 JSON 字段没有 schema 校验。

**评级：C+。**

### 2.5 “何时卖”

**实现：多出口；验证：最关键的价格参数仍未完成专门实验。**

代码实际存在：

- `stop`：最新箱体下轨首次跌破。
- `failed_breakout`：突破后短窗口回落。
- 初始保护止损：入场箱体上轨 × `sell.discount`。
- `raiseStops`：已确认新箱体下轨 × `sell.discount`，只升不降，且入场箱体不参与上移。
- `time_stop_noprofit`：`staledays=2`。
- 复权清仓/人工卖出路径。

必须严谨区分：

- 默认 `sell.discount=0.97` 已参数化；本次检索未找到 sell.discount 专门梯度实验的框架、数据或报告。不得声称 0.95/0.97/0.99 已测试，也不得据此称 0.97 最优。`docs/29` 中 P2-6b 是条件性 trail% 梯度研究，不等于 sell.discount 参数实验。
- 计划入场价 1.03 与计划止损价 0.97 的相对距离约为 `1 - 0.97/1.03 = 5.83%`，不能称“3%止损”。3%是止损价相对箱顶的折价，不是从买入触发价到止损价的完整风险距离。
- `raiseStops` 已接线不等于其保护效果已证明。docs/29 仍将“止损随 Box 上移事件研究”列为待做；当前尚缺效果研究证据。
- P2-6a 只说明 `staledays` 各档未达到采纳标准，不代表整个“何时卖”已验证完毕。

**评级：C+。**

### 2.6 “卖多少”


**实现：清仓规则明确；验证：计划到实盘执行差异未量化。**

`sellOrder` 计划卖出全部剩余持仓。这是订单意图，不代表真实成交一定全数完成；部分成交、未成交及跌停约束须按执行记录分别统计。

### 六问结论

六问均有规则或计划生成能力，但不能据此判为六问已被解决。当前关键约束是证据链、样本外验证与真实执行反馈尚未闭合。

## 3. 实验方法审计

### 3.1 做得好的地方

- 已形成“框架先行、生成器复现、报告沉淀”的实验资产体系。
- 明确 A 类后验分布、B 类端到端回测，遵守“先 A 后 B”。
- 已登记样本量、利润集中度、剔除前三、有效段数、复利/加法账区别。
- 已修正多次严重口径错误：用权益变动代替已实现净利、不同年集复利横比、半成品库误判 DONE、集中度分母错误等。
- A0 三路轨迹验证和各实验 HARD 校验是当前证据链的强项。

### 3.2 仍然存在的实验风险

#### 风险 A：参数选择偏差
2005–2018 同时承担筛选、调参、解释和表现展示。即使没有直接使用 2019+，也仍存在在同一历史段反复试错后选择规则的样本内偏差。

**整改**：把历史段切成“开发集 / 锁定验证集 / 最终样本外”，或者至少对每个新规则登记预注册假设、参数档位、失败判据和停止规则；完成后不得用结果反向改切点。

#### 风险 B：代表年结果不能替代全历史
P1-4 B 类和 LB-4 B 类使用代表年以降低成本，这适合筛选假设，不适合发布为生产最优结论。特别是 2015 对部分结果贡献很大。

**整改**：代表年只输出“是否值得补全”的门槛；任何生产参数变更前必须补跑固定全历史，且以端到端账户指标和逐年报告裁定。

#### 风险 C：A 类“相关性”容易被误读为可交易因果
LB-4 A 类显示成长速度与每单位净利单调相关，但这可能是强势股/样本选择的伴随现象。B 类准入实验框架对此有声明，但实验未完成。

**整改**：在报告标题和生产配置中区分 `observed association`、`rule backtest`、`out-of-sample result` 三种状态；A 类结论不得直接写入“已验证规则”。

#### 风险 D：跨库比较的资金内生性
文档已经承认不同量比档位会改变成交数、持仓竞争和资金分配。但这个问题必须成为生成器硬校验，而不能只写在报告中。

**整改**：每个 B 类报告强制输出：同年集、同初始权益、参数差集、成交数、被砍交易、资金占用、已实现净利和权益变动；缺任何一项不得生成“最优”。

## 4. 数据、回测与实盘现实审计

### 4.1 已确认的限制

- 2005–2018 使用现存股票数据，存在幸存者偏差。
- TDX 前复权日线用于早期价格，绝对价格和历史交易规则未完全恢复。
- 历史 ST 状态使用当前名称快照，不能完整还原当时 ST。
- 撮合器对次日成交、流动性、盘口深度和部分跳空行为有简化。
- 年末未平仓浮盈会进入 `equity_snapshot`，因此权益变动不能当作已实现净利。
- 真实系统是人工在券商端挂单和回录，回测的计划成交不等于实盘成交。

### 4.2 仍缺的硬证据

1. **计划→成交命中率**：按 buy/sell、stop/time_stop/failed/manual 分解。
2. **未成交后的策略行为**：首次事件不重发是设计选择，但必须量化漏单成本。
3. **实际滑点分布**：参数 `match.slippage=0.002` 是模拟假设，不是实盘测量。
4. **停牌、跌停、涨停、复权日清仓的逐笔审计**。
5. **样本外结果**：2019+ 当前被冻结，仍未成为正式考试。
6. **生产配置与回测配置的一致性证明**：尤其是 max_hold、equity_gate、MA60 gate 和新近增加的 `box.max_growth_days`。

### 4.3 14 年数字的正确解释

新基线报告给出终值约 4,420,990、CAGR 11.20%、MDD -14.14%，同时给出已实现合计约 +1,461,228、权益变动合计约 +1,988,710。两者不能混用。该结果只能说明：

> 在特定历史数据、特定复权、特定仓位、特定撮合和特定参数下，生产路径重放得到了一条历史资金曲线。

不能说明：

> 系统未来能获得 11.20% CAGR，或 0.97 止损、14 只持仓已经对未来最优。
