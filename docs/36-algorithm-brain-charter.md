## 第一法 · 状态机法

**Box 引擎是一个确定性离散状态机。** 法定状态集为五值枚举：
`forming`、`confirmed`、`broken_up`、`broken_down`、`invalid`。

**法定状态迁移**（贴近 `internal/box/engine.go`）：

```
[*] → forming                 扫描窗口中的首根可用 K 线
forming → forming             上轨未确认阶段创新高（更新候选并重置计数）
forming → forming             上轨已确认、仍在寻找下轨（枚举不变）
forming → confirmed           连续 N 日未再创新低 且 宽度校验（≥5% /top 口径）通过
forming → invalid             下轨确认前创新高，或宽度校验失败
invalid → forming            从触发失效的当根 K 线重启（invalidateAndRestart，
                              不计入箱体阶梯）
confirmed → broken_up        收盘 > top × buy.premium(1.03) 且 量能达标(前50日均量×
                              box.volmult) 且 非一字板
confirmed → broken_down      收盘 < 下轨
broken_up → forming          突破当根 K 线开启新 Box
broken_down → forming        跌破当根 K 线开启新 Box
```

**法定事实 1.1（forming 含两个隐藏子阶段）**：① 上轨候选阶段（top_confirmed 为空）；
② 上轨已确认、下轨候选/确认阶段（top_confirmed 非空、bottom_confirmed 尚空）。两者在
数据库枚举中都叫 forming，`forming_bottom` 是概念阶段不是真实枚举。

**法定事实 1.2（status 标签不是充分状态）**：完整状态向量还包含 topCandidate、topCount、
top、bottomCandidate、bottomCount、确认日期与前驱引用。**只看 status 一个字段，状态描述
是不完备的；不得以五状态标签构造「完备马尔可夫链」类推理。**

**法定事实 1.3（终态不可逆）**：terminal Box（broken_up/broken_down）不会回到 confirmed；
终止触发当根 K 线仅创建一个新 forming Box；prev_box_id 无环且时间顺序合法。

## 第二法 · 链路法（六层事件流水与四对象分离）

**法定事件流水**（每日批处理，全部按此顺序）：

```
截至交易日 T 的 OHLCV
  → Engine.Scan            重建 Box 序列（确定性、零 IO 纯函数）
  → BoxRepo.UpsertBoxes    保存状态投影（按上下轨价格对复用 ID）
  → Signal.Evaluate        只检查跟踪池 watch（watching/pending/holding）
  → signal 事件             breakout / stop / failed_breakout
  → Planner.Build          生成 T+1 计划与订单（观察期/持仓拦截/预算/价格偏离）
  → 次日成交？ → ledger.ApplyFill → 创建/更新 position，watch → holding
  → 后续止损/箱体退出/时间退出/人工退出 → 卖出 Fill 应用 → position 关闭
```

**法定铁律 2.1（四对象分离）**：**Box 状态、Signal 事件、PlanOrder 计划、Fill 成交、
Position 持仓是五种不同对象。** 「突破已发生」≠「系统已发信号」≠「已生成买单」≠「已经
开仓」。Box 的 broken_up 是入场链的**触发事件**，不是开仓事实——订单未成交、跳空越过
允许价格或被取消时，Box 已 broken_up 而账户没有持仓。

**法定铁律 2.2（position 是另一台状态机）**：open → open（stop_price 只升不降，数据库
触发器禁止下降）→ closed（卖出 Fill 将数量降至 0）。watch 与 position 是不同实体，
不得用 watch.stage 代替 position.status。**持仓期 Box 接触点只有移动止损候选**：
planner.raiseStops 读最新已落定 Box，候选止损 = bottom × sell.discount(0.97)，
仅当高于现有 stop_price 且非入场 Box 时上移。

**法定铁律 2.3（出口不止一种，不全由 Box 终态触发）**：

| 出口 | 触发语义 | Box 直接参与 |
|---|---|---|
| 最新 Box 下轨首次被收盘跌破 | signal stop → planner 按下轨×0.97 生成次日卖单 | 是 |
| 短期突破失败 | broken_up 后短窗口内收盘跌回该 Box 上轨之下 → failed_breakout | 是 |
| position.stop_price 保护单 | 初值 = 入场 Box top×0.97，之后随更高确认下轨上移 | 间接 |
| time_stop_noprofit | 持有达参数门槛仍未获利时退出（staledays=2） | 否 |
| 复权跳空清仓 / 人工卖出 | 撮合或人工路径 | 否 |

**Box broken_down ≠ position 已 closed**；反向，time stop 也能关闭 position 而 Box 未必
broken_down。**Box 状态图不能代替交易全系统状态图。**

## 第三法 · 数学边界法

**法定抽象：离散时间转移系统。**

```
X(t+1) = F(X(t), OHLCV(t+1), 参数)
```

X 不只是 status，还包括候选价、确认价、计数器、确认日、当前 Box 引用与谱系上下文。

**法定禁令 3.1**：**不需要微积分或微分方程**来实现达瓦斯 Box。给状态机硬套连续 ODE 会
丢失「连续 N 个交易日未创新高/低」这类离散守卫条件。

**法定禁令 3.2**：**五状态标签不构成完备马尔可夫状态**，不得声称它们之间的转移概率
都是 0 或 1——只保留标签时，下一步仍取决于价位、计数器、参数和新 K 线。

**法定禁令 3.3**：top × 1.03、bottom × 0.97、相邻箱体上轨差、箱体高度都是**数值计算**；
乘常数可称价格的**标量缩放**，但**不是 Box 状态之间的线性变换**——状态迁移是条件规则，
不是线性代数意义上的矩阵作用。

**法定分工 3.4（确定性与统计的边界）**：**规则如何执行是确定性问题；规则长期是否值得
执行是统计问题。** 执行层保持确定性（相同输入+参数+状态 → 相同信号）；概率统计只用于
验证确定性规则在历史样本中是否有稳定收益/风险表现，不得用于单次决策。

## 第四法 · 生命体五可验收属性

「生命体」是设计隐喻，**不得当作已实现事实**。法定验收契约：

| 属性 | 工程定义 | 当前状态 |
|---|---|---|
| 有状态 | 时点 t 有足够决定下一步行为的状态向量 | 单次 Scan 内成立（含候选价/计数器/确认日） |
| 有活动 | 新的按时间排序 K 线进入后按规则推进状态 | Scan 内每根 K 线调用 step |
| 有始 | 可回答逻辑出生时间、出生输入与前驱 | **缺口 L1**：无 start_date，800 根窗口首根 ≠ 真实出生 |
| 有终 | 可回答何时、因何进入不可逆终态 | **缺口 L2**：invalid 无独立失效日期/原因字段 |
| 可追溯、可复演 | 相同输入+参数重建相同轨迹并核对迁移 | 引擎确定性成立；**缺口 L3**：持久层无迁移事件账 |

**法定裁定**：Box 的算法心脏已经活了；可观测、跨重算稳定、带完整出生/死亡证据的领域
实体还没有完全落地。**「状态机计算正确」≠「生命周期事实可永久追踪」，两种成熟度必须
分开陈述。**

## 第五法 · 风险口径法

**法定事实 5.1**：入场触发价 = top × buy.premium(1.03)；初始止损 = top × sell.discount(0.97)。
按计划触发价衡量：

```
初始止损距离 = 1 − 0.97 / 1.03 ≈ 5.83%
```

**法定禁令 5.2**：**禁止在任何文档、报告、对话中把初始止损口头称为「3% 止损」。**
premium 3% 是入场触发加价，不是止损距离；两者相差近一倍。实际成交还可能因跳空、滑点、
整手取整改变实际风险——报告风险距离时必须标明口径（计划价 / 实际成交价 / 实际止损结果）。

## 第六法 · 生命周期边界法

**法定事实 6.1（窗口重算，非增量续跑）**：每日批处理读取最近 **800 根交易日 K 线**后
**重新计算**，不是从数据库恢复上一次 Box 的内部计数器后逐步更新。scanner 运行状态不跨
Scan 调用保存。

**法定事实 6.2（保存的是状态投影，不是事件账）**：UpsertBoxes 按上下轨价格对（格式化到
六位小数）寻找可复用 ID 后更新状态与前驱引用；`prev_box_id` 是当前重算序列的阶梯关系，
**不是独立追加、永不改写的生命谱系日志**。没有匹配且未被引用的旧记录可能被删除。

**法定事实 6.3（时间字段语义）**：`created_at` 是数据库行插入时间，**不是市场中的 Box
出生时间**；`broken_date` 可证明突破/跌破日期；invalid 无独立结构化失效时间/原因。
扫描结束时仍存活的 forming/confirmed 是「截至输入末尾的状态」，不是已死亡对象。

**法定事实 6.4（身份复用）**：数据库 ID 不是受契约保证的永久 Box 实例身份；相同上下轨
价格对可能参与 ID 复用。逻辑实例键与数据库代理主键必须区分表述。

## 第七法 · 缺口登记与验收顺序

**法定缺口总账**（解决前不得宣称「Box 完整生命史在生产数据中已自我完备」）：

| 编号 | 缺口 | 误判风险 | 验收方向 |
|---|---|---|---|
| L1 | 无 Box 逻辑 start_date | 无法证明出生时间/寿命 | 定义起始时间语义 |
| L2 | invalid 无终止日期/结构化原因 | 作废事件难审计 | 结构化 invalidated date/reason |
| L3 | 只有状态投影，无 transition event log | 看得到重算结果，看不到每步何时发生 | 先影子事件/离线对照，再决定事件表 |
| L4 | 固定 800-bar 窗口 | 窗口首 Box 左截断；窗口变化谱系变化 | 全量/800/增量三路径一致性测试 |
| L5 | 身份按价格对匹配复用 | 数值相同 ≠ 同一逻辑生命 | 明确逻辑实例键 |
| L6 | signal→plan_order 无显式外键 | 难将某次突破精确追到成交 | schema 设计时加强事件关联 |
| L7 | Box 下轨退出与 stop_price、time stop 并行 | 报表把退出混为一类 | 按 exit reason / 实际 Fill 分解统计 |
| L8 | 计划价风险距离 5.83% ≠ 口头「3%」 | 口径漂移 | 先写清定义，再做风险距离分布分析 |

**法定验收顺序（先验证轨迹，再判断规则，最后才动 schema）**：

```
A0 确定性与状态迁移契约（零策略变更工程测试）
   → A1 Box 生命周期可观测性（A 类零成本；左截断标 left-censored，未终结标右删失，
     不伪造出生/死亡日期）
   → A2 止损随 Box 上移事件研究（依赖 A0/A1 的事件日期与身份可信度）
   → A3 仅当 A0/A1 暴露结构性问题时才做 schema 设计（先 migration 方案再实现，
     禁止直接改已发布 migration）
```

**任何 L 缺口的修补，必须走 A0→A1→A2→A3 顺序，禁止跳步直接改 schema。**
