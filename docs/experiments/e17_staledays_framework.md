## 1 为什么是它

### 1.1 直接证据（P2-5 的结构发现）

2026-10-27 完成的 P2-5（1328 笔已平仓，14 年）得到一条不在原假设内的结构事实：

| 事实 | 数值 |
|---|---|
| 出口由 `time_stop_noprofit` 制造 | **836 / 1328 = 63.0%** |
| 这批合计净利 | **−905,208** |
| 其余 492 笔合计 | +1,748,007 |
| 持有天数中位（该批） | **恒为 5 个交易日** |
| 逐年符号 | **14/14 年全负**（无一年为正） |

规则本体（`internal/planner/planner.go:195-218`）：

```go
staleDays := p.st.ParamRepo.GetInt("position.staledays", 2)
n, _ := BarRepo.BarCount(pos.Code, pos.OpenedDate, planDate)  // 不含开仓日
if err != nil || n < staleDays { continue }
px, ok, _ := BarRepo.CloseOn(pos.Code, planDate)
if !ok || px > pos.AvgCost { continue }                        // 收盘高于成本则不动
// → 生成次日 stop_sell 卖单（trigger = 当日收盘价）
```

语义：**持有满 `staledays` 个交易日后，只要某日收盘 ≤ 成本，次日就以收盘价清仓**。
即「N 天不赚就走」。

### 1.2 为什么值得做

1. 它是十维 #9（移动 stop）里**唯一已实现、零工程成本、却从未验证过取值**的旋钮；
2. 它决定了 63% 的出口与账本最大的单一失血块（「亏损且持有 ≤10 日」合计 **−996,930**）；
3. P2-5 已否掉 trail%（H1 不成立，46 笔大赢家回吐中位仅 20.6%）——出场端剩下的
   唯一高杠杆变量就是它；
4. **零工程成本**：`--set position.staledays=N` 即可，不用改一行代码、不用 migration。

### 1.3 明确不做什么（防跑偏）

- 不改初始止损（`pos.StopPrice` / 箱体下轨止损）——那是 P2-6b 的地盘；
- 不改移动止损（新箱下轨上移）——同为 P2-6b；
- 不叠加任何其他维度（不做「staledays × 箱体高度」交叉表）——单变量纪律；
- 不改入场端任何参数（阶梯 `pos.newhigh.*` 原样继承基线）。

## 2 档位设计（跑前写死）

### 2.1 ⚠️ 代码事实纠正：`0` 不是「关闭」

`docs/29` §五 与 `docs/05` M10.2 原写「0（关闭）」，**这是错的**。
代码判据是 `n < staleDays → continue`，`staleDays=0` 时条件恒假 →
**所有持仓（含开仓次日）每天都进入判断**，是最**激进**的一档，不是关闭。

| staleDays | 代码行为 | 通俗语义 |
|---:|---|---|
| **0** | 恒进入判断 | 买入次日收盘不赚，第三日就走（T+1 极限） |
| **2** | n ≥ 2 起判断 | 第三日收盘不赚，第四日走（**当前生产/基线**） |
| 3 | n ≥ 3 起判断 | 比基线晚 1 个交易日 |
| 5 | n ≥ 5 起判断 | 晚 3 个交易日 |
| 10 | n ≥ 10 起判断 | 晚 8 个交易日（已放过短持窗口） |
| **off** | 永不触发 | `staledays=100000`（数值上界，非 0） |

**推论（写进判据，避免误读）**：`0` 与 `2` 只差 1 个交易日的启动点，
`2` 与 `3` 亦只差 1 天 —— 这三档预期差异小；**真正的梯度张力在 2 → 5 → 10 → off**。

### 2.2 档位确定（用户 2026-10-27 20:35 拍板）

| 档位 | staleDays | 角色 |
|---|---:|---|
| **收紧极限** | 0 | 「更快斩断」方向的唯一探针（恒进入判断） |
| **基线** | 2 | 当前生产/历史 14 年库所用值 |
| **放宽** | 5 | 晚 3 个交易日 |
| **放宽** | 10 | 晚 8 个交易日（已放过短持窗口） |
| **关闭** | 100000 | 数值上界，`n < 100000` 恒真 → 永不触发 |

**共 5 档。原梯度中的 `3` 被裁剪**，依据：`2 → 3` 只差 1 个交易日的启动点、
预期差异最小、信息量最低（框架 §2.1 的代码推论）。裁剪在**跑数前**决定，非看结果调整。

**为什么必须有 off 档**：没有上界锚就无法回答「放宽到多少才够」。若 off 最优，
则结论从「该调参」升级为「该规则本身有害」——这是性质完全不同的两种结论。

**若成本仍不可接受，裁剪顺序预先写死为：先砍 `0`，再砍 `10`；`2 / 5 / off` 三档为
最小可判定集合（能区分「现状 / 放宽 / 关闭」三种性质），不得再砍。**

## 3 数据与执行

### 3.1 执行方式

| 项 | 值 |
|---|---|
| 二进制 | `var/bt/darvas_e17.exe`（2026-10-24，**与 14 年历史基线同源**） |
| 源库 | `var/bt/full_hist_10pct.db`（只读） |
| 模式 | `backtest --mode regime`，逐年 `--from <y>-01-01 --to <y>-12-31` |
| 输出 | `var/bt/p26/p26_sd<N>_<year>.db`（独立 scratch，**绝不覆盖** `bt_e17_<year>.db`） |
| 执行器 | `scripts/p26_run.py`（串行、失败即停、参数从基线库读不手抄） |

**为什么必须用旧二进制**：`caac49f`（2026-10-27）的 A′ 50% 权益预算改变了仓位语义，
用当前代码编译会同时改动「staledays」与「仓位预算」两个变量。P2-6a 要求单变量，
故必须锁在与历史 14 年库同源的二进制上。新语义下的 staledays 梯度属 B-4 之后的复核，不在本实验范围。

### 3.2 单变量纪律

`--set` 只传 7 项：`pos.newhigh.cutoff / lookback / units.t1~t4 / newhigh_ladder`（从基线库读）
+ `position.staledays`（本次变量）。其余参数一律交给 migration 种子，与历史跑法一致。

**不得回灌基线库 param 表的全部 39 项**：其中混有引擎运行时回写的状态键
（如 `regime.bear_thresh`），回灌等于把「运行后状态」当初始值，引入未登记变量。

### 3.3 代表年（跑前写死规则 + 已选结果）

选择规则（预设，不按结果挑）：
1. 覆盖三种市况：结构牛（2006/2007/2015）、熊市（2008/2011/2018）、震荡（2012/2013/2017）；
2. 该年 `time_stop` 出口占比 ≥ 60%（否则实验对当年账本影响面太小）；
3. 笔数 ≥ 80（`closed`），保证有统计意义；
4. 成本 ≤ 2h/年（避免单档超时）。

按此规则选定（**在跑出任何 staledays 结果之前确定**）：

| 年 | 市况 | closed | ts_n | ts 占比 | ts 净利 | 单档耗时 |
|---|---|---:|---:|---:|---:|---:|
| **2012** | 震荡 | 118 | 91 | **77.1%** | −68,459 | ≈2h |
| **2017** | 结构市/蓝筹牛 | 108 | 83 | **76.9%** | −64,665 | ≈2h |
| **2011** | 熊市 | 116 | 81 | 69.8% | −79,152 | ≈1h |
| **2015** | 杠杆牛/崩盘 | 66 | 29 | 43.9%（<60%，**例外**） | −27,299 | ≈1.5h |

说明：2015 占比不达标，但它是 14 年里唯一的「杠杆牛→崩盘」样本，且当年 `time_stop`
绝对净利最小（−27,299）——若放宽在此年造成大幅回撤，是重要的负面证据，故**保留为压力年**。

**阶段划分**（成本控制）：
- **阶段 1（筛选）**：2012 × 5 档（`0/2/5/10/off`，≈10h，通宵）→ 看梯度形状；
- **阶段 2（确认）**：胜出档 + 基线档 2 档 × 2011/2015/2017（≈9h）；
- 阶段 2 只跑 2 档，避免 5 档全铺（否则 45h+）。

### 3.4 成本与串行

单年单档 1–2h；14 年全铺 × 6 档 = 100h+，**不做**。回测一律串行，不并发。

## 4 指标（每档每年必报）

### 4.1 主判据（擂台规则，`docs/29` §〇.1）

1. **代表年链接复利终值**：把代表年的 `ret_pct` 依次链接
   （`Π(1+r_y)`），而不是比较单年 `eq_end`——单年视角会被「好年/坏年」主导。
2. **代表年最大回撤（MDD）**：取各年 `maxdd_pct` 的最差值。
3. 采纳条件：**复利终值更高 且 MDD 不更差**（严格不劣化，容忍度见 §5.2）。

### 4.2 结构指标（判「怎么变的」，不给分）

| 指标 | 定义 | 为什么看 |
|---|---|---|
| `ts_n` / `ts_share` | time_stop 出口笔数与占比 | 变量是否真的生效（0 档应最低、off 档应为 0） |
| `ts_pnl` | 该批净利 | 直接对应 P2-5 的 −905,208 |
| 短持块净利 | 持有 ≤10 日的已平仓合计 | 最大失血块是否被止住 |
| 大赢家保留率 | MFE>50% 的笔数与该批净利 | **防切碎**：P2-5 已证 46 笔贡献 +1,133,049 |
| 持有天数分布 | 中位/均值/分位 | 梯度的机械后果 |
| 总笔数 / 胜率 / PF | 常规 | 交易频次是否被挤爆（放宽会占住仓位） |

### 4.3 仓位占用（放宽的隐藏代价）

`staledays` 放大会让亏损单长期占住仓位 → 一单位资金周转率下降 → **可能错过新信号**。
故必报：`总建仓笔数`、`平均持仓数`、`日均暴露`（若库内有权益/持仓序列）。

## 5 判定（预注册）

### 5.1 三条假设

- **H1（放宽有效）**：`staledays` 从 2 放宽到 5/10/off，代表年链接复利终值单调上升，
  且 MDD 不劣化 → 采纳「放宽」，P2-6a 结案并写 migration。
- **H2（现行最优）**：`2` 档的复利终值 ≥ 所有其他档 → 规则取值无需改动，
  出场端问题转向「入场端」（P1-4 升级为下一优先）。
- **H3（越严越好）**：`0` 档最优 → 说明「更快斩断」仍有余量，
  但须同时检查大赢家保留率（若 <30 笔则结论不可信）。

**三选一必居其一**；若出现非单调（如 5 最好、10 又回落），按 H2 处理并登记为
「无稳定最优、保持现状」——不得挑单点最优档去采纳（P0-1「总账最优是假象」教训）。

### 5.2 显著性口径（防小样本幻觉）

- 单年差异 < 3%（复利终值）视为**噪声**，不构成采纳依据；
- 任一档若 `closed` 笔数 < 60，该年结论标「样本不足」不参与判定；
- 代表年之间**方向不一致**（如 2012 支持放宽、2017 反对）→ 判定为「无稳定结论」，
  按 H2 处理。

### 5.3 采纳的工程代价（写清前置）

若 H1 成立需改 `position.staledays` 默认值 → **必须写 migration（append-only）**，
不得改旧文件（`docs/00` §5.6.9 教训：0017 种子曾让代码默认值变成死代码）。

## 6 HARD 校验（全跑前写死）

| # | 校验 | 通过标准 |
|---|---|---|
| ① | **基线可复现** | `p26_sd2_2012.db` 与历史 `bt_e17_2012.db` **逐笔一致**：`closed` 笔数、`Σrealized_pnl`、每笔 `code+opened_date+closed_date+pnl` 全等（容差 0.01 元）。**不一致则整个实验作废**，先查二进制/参数/迁移差异 |
| ② | 参数生效 | 各档库 `param.position.staledays` = 目标值；`off` 档 `ts_n` 必须为 **0** |
| ③ | 单变量 | 各档库除 `position.staledays` 外，其余 param 与基线库逐项相同 |
| ④ | 合计闭合 | 各档 `closed` 笔数 + 未平仓 = 该年建仓总数，不静默丢弃 |
| ⑤ | 结论可复算 | 复利终值、MDD、短持块净利由 `scripts/p26_report.py` 从库直算，报告数字与 JSON 一致 |
| ⑥ | 逐年齐备 | 每个代表年每档都有产物与耗时记录，缺档登记原因 |

**①是生死线**：若基线跑不回原样，说明存在未登记的语义漂移，
则所有档位的差异都无法归因于 staledays。
