## §1 目标与非目标

**目标**：6 个「从未验证」的入场/池管理旋钮，逐个回答「当前门槛划得对不对」——
两侧样本质量有无显著差异，被门槛拦下的样本是不是被误杀。

**非目标**：
- 不改门槛重跑回测（那是 B 类，若 A 类发现明确 edge 才立项）。
- 不做 `box.min_width`（维 2，B 类最贵，另列）、量比上限、跳空带（P2 新变量，另列）。
- 不碰 `pool.maxwatch`（已降级软参考）、`match.slippage`（成本非旋钮）、`buy.premium`（已收官）。

## §3 核心结论（先写，供跑数后回填验证）

### §3.1 旋钮 6 是死参数（**已代码级确认，非推测**）

`planner.go:584-601`：仓位决策是 `if ladder.enabled {阶梯制} else if market==Bull {A 判据升势}`。
新基线 `pos.newhigh_ladder=on`（已核实 param 表），故 `market==Bull` 分支**永不触发**。
`regime.a.lookback/up_bias/down_bias` 只服务 `regimeLabel()` 的 Bull 判定，而 Bull 判定在阶梯制下
不影响任何仓位/下注。→ **这三个键在新基线是死参数，无需分带，登记「已失效」即可**。

> 边界：`market` 仍写入 `reason_json.regime`（审计字段）并用于 MA60 闸门前的 regime 标注，
> 但 MA60 闸门读独立的 `gate.ma60.*` 参数，不读 `regime.a.*`。故 `regime.a.*` 的失效是干净的。

### §3.2 其余五旋钮的共同判据

A 类只回答「**已过门槛的样本内部还有无残余梯度**」+「**被门槛拦下的样本是否被误杀**」，
**回答不了门槛该定在哪**（那是 B 类改门槛重跑的事）。判据三条同时满足才判「有明确 edge，值得 B 类」：

1. **跨年一致**：带-年 n≥10 的年份里，方向一致年 ≥ 阈值；
2. **幅度超噪声**：每单位净利差 > 600 元（= 3% × 单位值 20,000）；
3. **剔除前三仍成立**：剔除每带前三赢家后方向不翻。

否则判「无稳定结论，维持当前门槛」，并如实登记（失败也要登记，不删）。

## §4 分带口径（逐旋钮，跑数前写死档界）

### §4.1 旋钮 1 `rs_excess_min`（相对强度门槛 0.20）

- **口径**：`candidate.reasons_json.rs_value`（screen 日快照，个股 20 日涨幅 − 上证 20 日涨幅）。
- **分带**：`<0.05 / 0.05–0.10 / 0.10–0.15 / 0.15–0.20 / 0.20–0.25 / 0.25–0.30 / ≥0.30`（对齐 docs/29 §七 676 行七档）。
- **关键**：candidate 表只存「过 box 形态门槛」的候选，rs_value 是**全量**（含 rs_pass=false 的，
  如 score 50 的票）。所以 `<0.20` 的低带是**真实存在的被拦样本**，可直接看它们最终赚不赚钱。
- **落地**：把 candidate 关联到最终是否成交（`plan_order`/`position`），算每个 rs 带的「成交后交易质量」。
- **注意内生性**：rs_value 高 → 股票本身强势 → 后续涨。这是「相对强度」的固有内生性，判据须看剔除前三。

### §4.2 旋钮 2 `latedays`（太晚放弃 4 日）

- **口径**：`too_late_days = BarCount(code, box.broken_date, screen_date)`，即突破后到 screen 日的交易日数。
  screener 只在 `n >= LateDays` 时写 `too_late_days` 并置 boxOK=false；`<4` 的样本**未写该键**，须复算。
- **分带**：`1 / 2 / 3 / 4 / 5–6 / ≥7`（对齐 docs/29 676 行「按信号后第 N 日成交分带」）。
- **落地**：对每只股票，取「首次 box broken_up 信号」的 broken_date，复算到 screen_date 的 bar 数，
  分带看「突破后第几天进场」与交易质量。
- **边界**：`latedays=4` 意味着「突破后第 4 天起放弃」；样本主要落在 0–3 日（能进场的），
  `≥4` 的只能从「被拦下」的 candidate 反事实看。

### §4.3 旋钮 3 `min_watch_days`（观察期 3 日）

- **口径**：`watch.added_date`（入池日）→ 首笔买单成交日的交易日间隔。
  planner 在入池后 `< min_watch_days` 个交易日不生成首买（`planner.go:164-170`）。
- **分带**：`0–2 / 3 / 4–5 / 6–10 / >10`（对齐 docs/29 678 行四档 0/3/5/10，观察期≠持仓）。
- **落地**：关联 watch 表与 plan_order/position，算「入池到首买」的实际间隔，分带看交易质量。
- **关键语义**：观察期只是「延迟首买」，不是「拒买」。被 min_watch_days 影响的样本是「首买被推迟」的，
  不是「被淘汰」的。→ 本旋钮的 edge 若有，是「观察期长短」对首买时机的影响，内生性弱于 rs。

### §4.4 旋钮 4 `flatboxmax`（横盘出池 4 箱）

- **口径**：watch 表 `exit_reason='flat_too_long'` 的出池样本（box_count 累计 ≥4 被横盘淘汰）。
- **反事实**：这些「被横盘淘汰」的票，出池后 N 日（20/60）涨了多少？若「被淘汰后大涨」的样本成片，
  说明 flatboxmax=4 误杀了潜在赢家；若「淘汰后继续横盘/下跌」，说明门槛合理。
- **分带**：`box_count 1 / 2 / 3 / ≥4（实际出池）`，看每带的「出池后 20/60 日收益」。
- **边界**：flatboxmax 是「连续 N 箱不涨就放弃」，本质是机会成本管理，不是交易结果旋钮。
  它的「对错」应看「被放弃的票后续表现」，而非「已成交交易质量」。

### §4.5 旋钮 5 `max_entry_gap`（跳空闸门 1.05）

- **口径**：`plan_order.status='cancelled'`（118 笔被弃，P1-4 已证）+ `ratio = ClosePx / trigger`。
- **背景**：P1-4 臂 C 已做「被弃 vs filled」反事实（结论：低胜率+厚右尾，无一致方向，2015 占比 10.2%）。
  但 docs/29 明确「没做梯度」——即「ratio 落在 1.03/1.05/1.08/1.10 各档时，被弃样本质量」。
- **分带**：`1.03 / 1.05 / 1.08 / 1.10`（对齐 docs/29 683 行四档），按被弃单的 `ClosePx/trigger` 分带，
  看每档「若放行，N 日收益」。
- **落地**：复算 118 笔被弃单的 ratio 与 N 日收益（照抄 matchOrder 入场价口径，P1-4 已定），
  分带看「跳空越大的被弃单，放行后收益越高还是越低」。

## §5 判定纪律（继承研究宪法 + 旋钮专属）

- 单年不结论、跨年才下结论；均值与中位数不可比。
- 不能跨库比「带」；本扫描全程同库（14 年 baseA），分带不改变资金分配，可比。
- 分带逐级加密，切点跑数前写死（本框架 §4 已写死），禁按结果合并/拆分/挪界。
- 每带必报：胜率 / 每单位净利 / 保本胜率 / 利润集中度 + PF + 缺口 + **剔除前三赢家净利**。
- **被弃样本反事实**（§4.4/§4.5）必须照抄成交价口径，不与全体 1560 笔比，强制报 2015 占比（>40% 降级为「2015 年声明」）。
- 结构性无样本登记「不可检验」，不写「无效应」（与 box 高度 0–5% 带、量比 0–2× 带同一类问题）。
