## ⚠️ 勘误 · 立项前提已推翻，实验重定向（2026-11-02）

### 一、原立项前提崩塌

本框架原问句是「把『除权日强制清仓』改成『除权日继续持有』是否更优」，其前提是 T3 报告
（`e17_sell_discount_report.md`）的结论——**「`dividend_clear`（复权跳空日强制清仓）是代表年唯一正收益来源，
三档合计 +39.5万~+44.2万、胜率 86~88%」**。

用真实除权记录反查这 44 笔 `sim:dividend` 成交后，前提被证伪：

| 项 | 数值 |
|---|---|
| 44 笔里真除权 | **7 笔（16%）** |
| 44 笔里跌停误判 | **37 笔（84%）** |
| 真除权贡献已实现 | +28,068 |
| 跌停误判贡献已实现 | **+367,594** |

**真正的正收益来源是「跌停日以昨收×0.998 高价逃顶」，不是除权清仓。** 真除权只贡献 +2.8 万，
体量不足以支撑「复权后继续持有」的 B 类实验立项。

### 二、bug 本质

`isDividendGap` 用「close 相对昨收跌幅 > 阈值（主板 0.09）」反推除权，而主板跌停恰是 10% →
**所有一字跌停/接近跌停都被误判成除权**，在跌停日以接近跌停前价格强制清仓，歪打正着避开后续连续下跌。
除权幅度是连续的（0%~65%，纯派息日跌幅常 <3% 甚至上涨），与跌停 10% 大量重叠，**阈值无法二分**。

### 三、修复（已落地并提交）

- `migration 0022` 新增 `dividend_event` 表（真实除权记录，PK(code,date)）；`DivRepo.IsDividendDay` 查表。
- `match.go` 除权识别从价格反推改为查真实记录；清仓价从 `slip("sell", prev.Close)` 改为 `today.Close`（除权后实际价）。
- 删除死代码 `isDividendGap` / `gapThreshold`（bug 根源）。
- 灌库：源库灌入 59,665 条 Type=1 真实除权事件（覆盖 5,531 只）。
- commit：`e749349`（引擎修复）+ `b62bdd2`（灌库脚本）。

### 四、修复验证结果（2017 代表年，`var/bt/t7fix_test/bt_fix_2017.db`）

| 项 | 修复前 | 修复后 |
|---|---|---|
| sim:dividend 成交笔数 | 44 笔 | **13 笔** |
| 其中真除权 | 7 笔 | **13 笔（100%）** |
| 其中跌停误判 | 37 笔 | **0 笔** |
| 2017 已实现合计 | — | **−213,136.75** |

13 笔 `sim:dividend` **全部命中 `dividend_event` 表真实除权日（13/13）**，跌停误判彻底归零。
（13 > 修复前 7，是因为查真实记录能识别出价格反推漏掉的「跌幅不大的纯派息除权日」，识别更全更准。）

### 五、重定向后的新问句

原「复权后继续持有 vs 强制清仓」作废。真正的问句变成：

> **「跌停日强平」这个歪打正着的 edge 是不是真的、要不要显式化成一条撮合层规则？**
> 这跟除权无关，是「跌停日逃顶」策略。重定向后的实验框架另立新文件（待建）。

## §1 要回答的一个问句 + 回答不了的六件事

### 1.1 问句

**把「除权日强制清仓」改成「除权日按调整价继续持有」，端到端是变好还是变坏？更根本地——当前体系在代表年里的正收益，到底有多少是「复权强制清仓」这条撮合层规则送的、多少是达瓦斯策略自己挣的？**

### 1.2 明确回答不了

| # | 回答不了 | 原因 |
|---|---|---|
| 1 | 「继续持有」的最优实现（是否补仓、持有多久、何时再触发止损） | 只测「持有 vs 清仓」一个二值切换，继续持有内部的细化策略须另立实验 |
| 2 | 复权清仓的「分」是不是可归因的 alpha | 清仓价 = 昨收×(1−滑点) 是**构造性偏正**（刻意避开跳空损失），本实验只能度量「这个规则贡献了多少」，不能证明它是市场给的 edge |
| 3 | 因果 | 复权日处置改变会内生改变资金分配（持有占用仓位 → 不同标的被买入），端到端差异不是纯「除权日」效应 |
| 4 | 真实除权记录的完备性 | TdxQuant 除权记录自身可能有漏/误，`hold_adjusted` 档的准确性依赖数据源质量，须在 §5 前置门槛里做交叉校验 |
| 5 | 样本外有效性 | 2005–2018 是全部参数被选定的同一段历史，结论只提假设 |
| 6 | 2019+ 表现 | 数据冻结（`docs/00` §9），不碰 |

## §2 变量语义：一个规则，两条实现路径（本实验的核心难点）

现状（`match.go` §3.8 + `isDividendGap`）：

```
① 识别除权日：close 相对昨收跌幅 > 涨跌停阈值（主板 9%、科创/创业 19%）→ 判为除权跳空
② 处置：持仓股强制清仓，清仓价 = prev.Close × (1 − slippage)
③ 副作用：清仓后在途止损/突破单同步作废；复权后箱体重算、重新出信号
```

本实验的两档：

| 档 | `dividend_handle` | 识别除权日 | 处置 |
|---|---|---|---|
| A（现状基线） | `force_close` | 价格反推 `isDividendGap`（**不查真实记录**） | 强制清仓 |
| B（改造） | `hold_adjusted` | **真实除权记录**（TdxQuant `get_divid_factors` 的 `Type=1` 除权除息日） | 除权日**不清仓**，按除权后的调整价重算箱体 top/bottom 与止损位，继续持有 |

**关键差异点（必须预注册，跑前定死）：**

1. **识别口径**：A 用价格反推（有误判/漏判），B 用真实记录（有数据源依赖）。两档的除权日集合**本身就不一致**，这是实验的一部分，不能事后归因成「识别差异 vs 处置差异」混淆。
2. **B 档的持仓价口径**：除权后持仓的成本价、箱体、止损如何调整，是 B 档的实现细节，必须在 §3 预注册死，否则 B 档结果不可复现。

## §3 B 档（`hold_adjusted`）的实现规格（预注册，跑前定死）

> 这是本实验最易「边跑边改」的部分，全部写死。

### 3.1 除权日的判定

- 用 TdxQuant `get_divid_factors` 拉到的 `Type=1`（除权除息）记录，其 `Date` 作为**真实除权日**集合。
- 落库表：`dividend_event(code TEXT, date TEXT, bonus_10 REAL, share_bonus_10 REAL, allot_10 REAL, allot_price REAL)`，`bonus_10` 等为**每 10 股口径**（已钉死，`docs/42` §5.2）。
- 引擎在撮合日若命中 `dividend_event` 的 `date`，走 B 档处置，**不再走 `isDividendGap` 价格反推**。

### 3.2 除权后的持仓调整（关键，逐条写死）

| 调整项 | 规则 |
|---|---|
| 持仓数量 | 按送股/扩缩比例调整：`qty_new = qty × (1 + share_bonus_10/10)`（配股另计，初版**不含配股**，遇配股记录跳过并登记） |
| 成本价 | 按除权除息公式下调：`cost_new = (cost − bonus_10/10) / (1 + share_bonus_10/10)` |
| 箱体 top/bottom | 除权日按同比例下调（除以复权因子），保持相对位置不变 |
| 止损位 | 按同比例下调，**不触发**（除权本身不是价格信号，是口径调整） |
| 后续 | 除权后继续按达瓦斯规则运行：突破新箱顶买入逻辑不变、raiseStops 不变、time_stop 不变 |

### 3.3 明确不做（防止 B 档变味）

- **不补仓**：除权后不因为「变便宜」而加仓，保持原仓位量（除送股自然增加外）。
- **不改变止损算法**：`sell.discount=0.97`、`staledays=2`、`max_hold=14` 等 T3 已定参数全部不变。
- **不处理配股**：初版遇到 `Allotment>0` 的记录跳过并单独登记，配股是另一类事件，不混入。

## §5 出口分解方案（预注册，跑前定死）

### 5.1 主分解：除权日的处置去向（回答 §1.1 的核心）

对 B 档，把「A 档本来会 `dividend_clear` 的那批持仓」单独跟踪：

| 标签 | 定义 |
|---|---|
| `would_have_cleared` | A 档在除权日强制清仓的持仓，在 B 档中的**最终去向** |
| ↳ `held_then_stop` | 继续持有后最终被止损/时间止损出场 |
| ↳ `held_then_win` | 继续持有后最终盈利出场 |
| ↳ `held_still_open` | 年末仍持有（浮盈计入权益变动，不计已实现） |

**必报**：这 42~44 笔（代表年）在 B 档下的**已实现净利之和**，与 A 档的 `dividend_clear` 已实现（+39.5万~+44.2万）直接对账。

### 5.2 副分解：策略出口（同 T3 标签 A，口径一致）

沿用 T3 的标签 A：`time_stop_noprofit` / `stop` / `initial_stop`（含标签 B 上移与否）/ `dividend_clear`（B 档应趋近 0 或消失）/ `manual`。**用同一套出口标签，才能把 A/B 两档的「策略出口裸表现」直接比。**

### 5.3 为什么这样分解能回答 §1.1

- §5.1 直接回答「复权清仓那批仓位，如果不砍，结局如何」——这是 +42万 是否「假 edge」的判决依据；
- §5.2 回答「除权处置改变后，策略出口本身有没有变化」——排除资金分配内生性干扰。

## §6 判定规则（预注册，跑前定死）

### 6.1 主判定（阈值沿用 `docs/29` §六第 6 条）

- 端到端每单位净利差 |Δ| < **600** → 不可分辨（钝）；
- |Δ| ≥ 600 且方向稳定 → 可分辨。

### 6.2 三个预设结论（防事后找理由）

| 结论 | 触发条件 | 含义 |
|---|---|---|
| **假 edge 坐实** | B 档「那批仓位」继续持有后**已实现净利转负或显著低于** A 档 dividend_clear 的 +42万 | 复权强制清仓是「砍在高点」的确定性红利，不是市场 alpha；**保留强制清仓，T7 收官** |
| **真机会** | B 档继续持有后净利 ≥ A 档，且剔除前三赢家后仍成立 | 复权后继续持有是真 edge，进入引擎改造落地评估 |
| **无差别** | 端到端 Δ < 600，那批仓位 B 档结局与 A 档相当 | 复权处置是噪声，按「简单/可审计」原则保留现状 |

### 6.3 必报表（缺一即视为报告不合格）

每档 × 每年：已实现净利 / 权益变动 / 胜率 / PF / MDD / 水下天数 / 出口数 / 未成交率 / 最差年 / 剔除前三赢家净利 / **§5.1 的那批仓位去向分解**。

## §8 反模式禁令（违反即实验作废）

1. **禁止事后调 B 档实现规格**——§3 已写死的调整规则，跑出结果不许改，要改先改框架再重跑。
2. **禁止合并 A/B 两档的「除权日集合差异」**——A 用反推、B 用真实记录，识别口径不同是实验的一部分，不许事后归因成「识别差异」掩盖处置差异。
3. **禁止用「含复权清仓」的全口径比**——A 档的 dividend_clear 偏正，B 档可能没有这项，必须用 §5.1 的「那批仓位去向」对账，不许拿全口径总数硬比。
4. **禁止把「继续持有后浮盈」当「已实现」**——年末仍持有的按权益变动口径，不进已实现净利（`docs/29` §2.5.2 铁律）。
