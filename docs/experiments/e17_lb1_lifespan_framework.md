## §1 实验目的与边界声明

### 1.1 本轮要回答的一个问句

box 从「confirmed（下轨 3 日确认完成）」到「broken_up（突破）」这段**存续交易日（寿命）**，与**突破后这笔交易的质量**是什么关系？

- 具体化：把每一笔已平仓交易的「入场 Box 的寿命」分带，看各带的**胜率 / 每单位净利 / 保本胜率 / 利润集中度 + PF + 剔除前三赢家净利**有没有梯度。
- 这是「Box 生命体征」六体征（出生/成长/阶梯/寿命/死亡/谱系）里的**寿命**体征，是达瓦斯「箱体像金字塔层层叠加」的时间维度量化，不引入任何新理论（`docs/00` §3.6 唯一理论约束）。

### 1.2 本轮明确回答不了的五件事

| # | 回答不了 | 原因 |
|---|---|---|
| 1 | **因果** | 「寿命长/短」与「突破质量」高度混杂：老 box 突破时距 52 周高点更近（第 5 维）、量比分布不同（第 7 维）等。本实验只报**相关性分布**，不下因果结论。 |
| 2 | **寿命该定多少才算「好」** | 本实验是 A 类分带统计（已有交易按寿命分组），**不改回测器**。若发现某带有 edge，须另立 B 类（改 box 确认/突破节奏重跑），不在本实验范围。 |
| 3 | **样本外有效性** | 2005–2018 是全部参数被选定的同一段历史（`docs/29` §八.6），结论只用于提假设。 |
| 4 | **其他五体征** | LB-2（阶梯速度）/ LB-4（成长速度）/ LB-5（谱系深度）/ LB-3（出生方式）/ LB-6（死亡模式）不在本实验，LB-1 只做寿命。 |
| 5 | **2019+ 样本** | 规则定稿前禁碰（`docs/29` §八.6）。 |

### 1.3 结论句式模板（强制措辞）

跑完写结论时，必须按以下句式组织，不得省略括号内的限定项：

> 在 2005–2018 的 __ 笔已平仓交易中，可复算寿命 __ 笔、不可复算 __ 笔；寿命四带（<3 / 3–10 / 10–30 / >30 交易日）的每单位净利分别为 __ / __ / __ / __，胜率 __ / __ / __ / __。
> H1（寿命与突破质量单调相关）**成立/不成立**；H2（短寿命 box 突破质量差）**成立/不成立**。
> 「寿命该定多少阈值」**本实验不回答**，只能由后续 B 类回测回答。

禁止出现的写法：`老 box 更好`、`寿命越长越赚`、`该等 box 成熟后再买`。

## §2 实验假设（可证伪形式）

> **口径前置说明**：本实验的「寿命」是**入场 Box 的存续交易日**，不是持仓持有天数。
> 两者是不同概念：寿命 = box 从 confirmed 到 broken_up 的时间；持仓天数 = 从买入到卖出的时间。
> 本实验研究前者与「这笔买入的质量」的关系。

| 编号 | 假设 | 判据（同时满足才算成立） | 证伪条件 |
|---|---|---|---|
| **H1** | **寿命与突破质量单调相关**：寿命越长的 box，突破后交易质量越高 | L1 四带的每单位净利，4 个相邻对中 **≥ 3 个**随寿命递增（严格大于） | 递增对 < 3 → **不成立**（记为「无单调梯度」） |
| **H2** | **短寿命 box 突破质量差**：寿命 <3 交易日的 box（「刚确认就突破」），突破后是负 edge | `<3 日` 带的每单位净利 **< 0**，且该带 `n ≥ 30`，且剔除前三赢家后净利仍 **< 0** | `<3 日` 带每单位净利 ≥ 0，或剔除前三翻正 → **不成立** |

**H1 与 H2 不是互补关系。** H1 关心「全谱有没有单调梯度」，H2 关心「最左端那一带是不是坑」。可以 H1 不成立但 H2 成立（只有短命 box 特别差、其余打平），也可以都成立/都不成立。裁定允许四种组合，**禁止**为叙事漂亮压成二选一。

**判据阈值（≥3 递增对 / <3 日每单位 <0 / n≥30）在跑数之前写死**，不得看结果调整。

## §3 数据准备过程

### 3.1 只读纪律

- 一律用 `sqlite3.connect("file:<db>?mode=ro", uri=True)`。
- 不写回测库、不碰生产库 `darvas.db`（`docs/06` §6.2 库隔离）。
- 不重跑任何回测、不改任何参数、不重建任何索引。

### 3.2 取数口径

**关联链**（`entry_box_id` 在新基线库全为 NULL，须反向匹配，见 §3.3）：

```
position ──leg_no=1──▶ position_leg ──plan_order_id──▶ plan_order
   │                                                      │
   │ status='closed'                                      │ reason_json.box_top / box_bottom
   │ realized_pnl                                         │ signal='breakout'
   ▼                                                      ▼
  交易样本                                      code + box_top + box_bottom
                                                        │ 精确匹配
                                                        ▼
                                                    box 表（入场 Box）
                                                        │ bottom_confirmed（confirmed 日）
                                                        │ broken_date（突破日）
```

单库两条 SQL：

```sql
-- ① 交易样本（复用 P2-5 的成本口径：cost_basis 从 legs 求和，position.qty 平仓后清零）
SELECT p.id, p.code, p.realized_pnl, p.close_reason,
       tp.execute_date AS ex_date, o.reason_json,
       (SELECT SUM(qty)       FROM position_leg WHERE position_id=p.id) AS qty,
       (SELECT SUM(qty*price) FROM position_leg WHERE position_id=p.id) AS cost_basis
FROM position p
JOIN position_leg l ON l.position_id=p.id AND l.leg_no=1
JOIN plan_order o ON o.id=l.plan_order_id
JOIN trade_plan tp ON tp.id=o.trade_plan_id
WHERE p.status='closed'

-- ② 入场 Box 匹配（用 reason_json 里的 box_top/box_bottom 精确匹配）
SELECT id, bottom_confirmed, broken_date, top, bottom, status
FROM box WHERE code=? AND ABS(top-?)<1e-6 AND ABS(bottom-?)<1e-6 AND status='broken_up'

-- ③ 寿命交易日计数（该 code 的 daily_bar 在 [bottom_confirmed, broken_date] 的行数）
SELECT COUNT(*) FROM daily_bar
WHERE code=? AND date>=? AND date<=?
```

提取字段：

| 字段 | 来源 | 用途 |
|---|---|---|
| `year` | 库文件名 `bt_baseA_<year>.db` | 逐年分组 |
| `realized_pnl` | `position` | 实际盈亏（净额，含双边费用） |
| `qty` / `cost_basis` | `position_leg` 求和 | 成本口径（§3.3 陷阱） |
| `units` | `reason_json.units` | 每单位净利分母 |
| `box_top` / `box_bottom` | `reason_json` | **反向匹配 box 的键** |
| `signal` | `reason_json` | 确认为 breakout（入场信号） |
| `bottom_confirmed` | `box` | 寿命起点（confirmed 日） |
| `broken_date` | `box` | 寿命终点（突破日） |
| `lifespan_days` | ③ 计数 | 寿命 = broken_date − bottom_confirmed 的交易日数 |
| `newhigh_distance_pct` | `reason_json` | 附录切片（与第 5 维交叉） |

### 3.3 两个必须绕开的陷阱

**陷阱一：`entry_box_id` 在新基线库全为 NULL。** 实测 2015 库 80 笔 position 的 `entry_box_id` 全为 NULL。
原因是 `internal/ledger/ledger.go:405` 的 `entryBox = reasonBoxID(order)` 从 `reason_json.box_id` 读，而
`internal/planner/planner.go:630-637` 构造 reason 时**没有写 `box_id` 字段**（该字段在现行新基线二进制里是死代码路径）。
**绕开方式**：用 `reason_json` 里确实存在的 `box_top` / `box_bottom` 两个价格 + `code` 三元组反向精确匹配 box 表
（`ABS(top-?)<1e-6 AND ABS(bottom-?)<1e-6`），实测唯一命中（§3.4）。

**陷阱二：`position.qty` 在平仓后被清零。** 成本一律从 `position_leg` 求和（`cost_basis = Σleg.qty×leg.price`），
与 P2-5 同口径（P2-5 已证 `avg_cost × qty ≡ Σ(qty×price)` 逐笔相等）。

### 3.4 反向匹配的唯一性验证（HARD 前置）

`(code, box_top, box_bottom)` 三元组在 box 表里的命中必须是唯一的。若出现多命中（理论上同一票在相近价位反复成箱），
取 `broken_date` 与 `execute_date` 最接近的一条（容差 ≤ 2 交易日），仍不唯一则标「匹配失败」，进不可复算登记。
实测（§3.2 已验证 sh600653 top=3.65 bottom=3.27 → 唯一命中 box id=3698）。

### 3.5 寿命的口径边界（`docs/36` 第六法）

- **起点 = `bottom_confirmed`**：box 状态机里 confirmed 的判定就是「下轨 3 日确认完成」（`bottom_confirmed` 非空）。
  引擎没有独立的 `confirmed_date` 字段，`bottom_confirmed` 就是 confirmed 语义的事实载体（`docs/36` 法定事实 6.3）。
- **终点 = `broken_date`**：突破发生的那一天。
- **寿命 = [bottom_confirmed, broken_date] 区间内该股 daily_bar 的行数（含两端）**。
  注意：突破当日（broken_date）也是「box 存续」的最后一天，故含两端。
- **800 根窗口左截断**：`docs/36` 缺口 L4——每个回测库只存最近 800 根 K 线重算后的 box。
  若某 box 的 `bottom_confirmed` 落在窗口左边界之外，其寿命被截断、**偏短**。这是本实验的已知系统性偏差
  （会**低估**长寿命 box 的数量），登记在 §9，结论章必须携带。

### 3.6 样本漏斗（跑前登记，结构锚点）

| 步 | 说明 | 预期 |
|---|---|---|
| 1 | 14 个回测库（2005–2018） | 14 库 |
| 2 | `status='closed'` 且有 leg1 | **1481 笔**（§0 实测） |
| 3 | reason_json 缺 `box_top`/`box_bottom`（非 breakout 信号） | 登记，不进寿命分带 |
| 4 | 反向匹配 box 失败（无唯一命中） | 登记「不可复算」，不进寿命分带 |
| 5 | **可复算寿命样本** | 待跑数，见报告 |

### 3.7 已知数据偏差（结论必须携带）

- **未复权（`adj_factor` 恒 1.0）**：box 的 top/bottom 是未复权价。持仓期若除权，`box_top`/`box_bottom`
  与 reason_json 记录的原始值一致（都是同一时刻的未复权价），故匹配不受影响；但跨除权日的 box 边界本身可能有语义噪声。
- **800 根窗口左截断**（§3.5）：长寿命 box 被系统性低估数量。
- **幸存者偏差**：只用当前仍存在的股票，退市股不在样本内。
- **无基线对照不构成缺口**：本实验只统计新基线自身，与账本基线（1328 笔）是不同仓位语义，不横比（`docs/29` §〇）。

## §4 口径定义

### 4.1 核心两式

```
lifespan_days = 该 code 的 daily_bar 在 [bottom_confirmed, broken_date] 的行数（含两端）
pu            = realized_pnl / units          # 每单位净利（units 取自 reason_json.units）
```

### 4.2 为什么寿命用「交易日计数」而不用「自然日相减」

达瓦斯箱体的推进是**逐交易日**的（每根 K 线推进一步状态机，`docs/36` 第一法）。停牌期间 box 不推进，
自然日相减会把停牌天数误算进寿命。故用 `daily_bar` 行数计数，与引擎语义一致。

### 4.3 统计口径（每带必须齐备，与 P0-1 / P2-5 同构）

| 口径 | 公式 | 备注 |
|---|---|---|
| 胜率 | `wins / closed` | 已平仓头寸中盈利占比 |
| 每单位净利 | `Σpnl / Σunits` | `units` 集合 ⊆ {0.5, 1, 2, 3} |
| 保本胜率 | `1 / (1 + 平均盈利/|平均亏损|)` | 即 `|avgLoss| / (avgWin + |avgLoss|)` |
| 利润集中度 | 前三赢家合计 / 毛盈利 | 无毛盈利或前三合计为负时记 `—` |
| 附加 A | 利润因子 PF = 毛盈利 / |毛亏损| | |
| 附加 B | **缺口** = 实际胜率 − 保本胜率（pp） | `docs/29` §八.2 判定用 |
| 附加 C | **剔除前三赢家净利** | 识破「假 edge」的关键列 |
| 附加 D | 剔除前三赢家每单位净利 | 同上 |

### 4.4 分带驱动变量（寿命）

`lifespan_days` 分四带（§5.1）。本实验**不做**「持有天数 vs 寿命」的交叉（那是 LB 与 P2-5 的交叉验证，
留待后续），只报寿命这一个分组变量（OFAT，`docs/29` §2.3）。

## §5 分带设计

### 5.1 主带：寿命四带（预设规则，禁止按结果合并）

```
[1,3)  [3,11)  [11,31)  [31,+∞)
```

即 **<3 交易日 / 3–10 交易日 / 10–30 交易日 / >30 交易日**。

**切法直接照抄任务书预设**（`<3 / 3-10 / 10-30 / >30 天`），不按结果调整。
理由：3 日 = 三日法则的确认周期（box 刚 confirmed 的「最短寿命」下限，<3 日意味着「刚确认即突破」，是「短寿命」的极端形态）；
10 日 ≈ 两周、30 日 ≈ 一个半月，是 A 股行情节奏的自然分界。**这些边界是预设，不是拟合拐点。**

### 5.2 样本不足的加密规则

- 若某带 `n < 30`，按 §7.1 标「样本不足」，**不合并**（`docs/29` §2.5.1 第 4 条）。
- 若 `>30 日` 带 `n < 30`（长寿命 box 本就稀少 + 800 根窗口截断加剧），在报告里单列并标「样本不足」，不得并入 10–30 日带。
- **不做 L2/L3 二级加密**（P0-1 的分带加密是针对「连续百分比」的；寿命是离散交易日，四带已足够，加密只会产生空箱）。
  若结果出现「某带每单位净利异常高、集中度 >50%、剔除前三翻负」，按 §7.3 直接裁定为「假 edge」，不再降粒度。

### 5.3 空带与不可复算样本的呈现规则

- **不可复算样本**（reason_json 缺 box 字段 / box 匹配失败）**不进寿命四带**，单设「不可复算」子集行，
  标注「子集标记，非加总行」，印出它自己的笔数、胜率、每单位净利。
- 加总恒等式：`Σ(寿命四带 n) + 不可复算 n = 1481`。

### 5.4 逐年矩阵

14 年 × 4 带，每格印「净利（笔数）」。缺失年份登记原因，**不得留空**（HARD 校验 §7.5）。

## §7 判定标准

### 7.1 三条硬门槛（缺一不得下结论）

1. **样本量**：`n ≥ 30`；不足则标「样本不足，仅供参考」。
2. **有样本年数**：`Mf ≥ 8`（过滤后「该年该带 n≥3」的年数）；不足则标「出现年数不足，不作跨年裁定」。
3. **完整性**：四项固定口径 + PF + 缺口 + 剔除前三，缺一项即不得下结论。

### 7.2 跨年一致性记账规则

- `M` = 该带 `n > 0` 的年数；`P` = 该带年度净利 > 0 的年数。
- **过滤后符号统计**：只把「该年该带 `n ≥ 3`」的年计入 `P'` / `M'`，**判定用过滤后那一组**。
- 记分卡必须**同时印出** `P/M` 与 `P'/M'`。
- `longest_run` = 最长连续同号年数（对应 `docs/29` §八.3「连续 ≥2 年同符号」）。

### 7.3 逐带裁定矩阵（与 P0-1 同构，便于横向对比）

| 条件 | 裁定标签 |
|---|---|
| `n < 30` | **样本不足** |
| `n ≥ 30` 且 `Mf < 8` | **出现年数不足** |
| `n ≥ 30`、`Mf ≥ 8`、`pos_ratio' ≥ 0.70`、缺口 ≥ +2pp、剔除前三仍为正 | **edge** |
| 同上但剔除前三为负 | **假 edge（少数交易撑起）** |
| `pos_ratio'` 在 0.30–0.70 | **不稳定（不得下 edge 结论）** |
| `pos_ratio' ≤ 0.30`、缺口 ≤ −2pp | **负 edge** |

判定顺序：**先查剔除前三是否翻负（假 edge）→ 再查跨年稳定性**（P0-1 附 A 方法论修正 1，本实验继承）。
补充：缺口在 ±2pp 之间一律记「无 edge」。

### 7.4 H1 / H2 的裁定输出

两条假设**各自独立裁定**，输出格式固定为：

```
H1 [成立/不成立]  递增相邻对 __/4（需≥3）  四带每单位净利 __ / __ / __ / __
H2 [成立/不成立]  <3 日带每单位净利 __（需<0）  n=__（需≥30）  剔除前三 __（需<0）
```

| # | 校验 | 判据 |

| HARD① | **样本总对账**：Σ 各库 closed 笔数 = 1481 | 严格相等 |

**执行中的方法论修正与结构性发现**：

1. **反向匹配 `(code, box_top, box_bottom)` 唯一命中率 100%**（1481/1481，仅 1 笔多命中按 broken_date 最新取一）。
   这验证了框架 §3.3 的绕开方案成立：新基线库 `entry_box_id` 全 NULL（reason_json 无 `box_id` 字段），
   但 `box_top`/`box_bottom` 价格对作为逻辑键是可靠的。**建议在后续 LB 系列与「止损随 box 上移事件研究」中沿用此关联键。**

2. **结果方向与 P2-5 相反，但两者不矛盾**：P2-5 证「持仓天数越长每单位净利越高」（持有时间=唯一赚钱因子）；
   本实验证「box 寿命越短每单位净利越高」（1-2 日 +2,127 → 30 日+ +488，单调递减）。
   两者分属不同维度——「box 存续时间」与「持仓持有时间」是独立变量，不可混读。
   一个可能的机制解释（仅登记，不验证）：box 寿命短 = 突破来得快 = 上涨动能足；寿命长 = 磨了很久才破 = 突破偏钝。
   但这是叙事，不是证据，须由 LB-2（阶梯速度）/LB-4（成长速度）联验后才能定性。

3. **两个端带都是「假 edge」**：1-2 日带每单位 +2,127 全表最高，但 n=21 样本不足、集中度 83%、剔除前三翻负 −1,824；
   30 日+ 带每单位 +488 最低、PF 1.66 最低、集中度 41.3%、**剔除前三 −10,357 翻负** → 裁定「假 edge」。
   只有 3-10 日（+195,010）与 11-30 日（+256,303）剔除前三仍为正，是真实但递减的贡献。
   **这再次印证「剔除前三」是识破假 edge 的关键列**（P0-1 教训在本实验复现）。
