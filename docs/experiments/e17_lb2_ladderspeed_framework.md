## §1 实验目的与边界声明

### 1.1 本轮要回答的一个问句

box 的**阶梯速度**（这只股票从上一级箱体突破到本级箱体突破，爬一级台阶花了多少交易日）与**突破后这笔交易的质量**是什么关系？

- 具体化：把每一笔已平仓交易的「入场 Box 相对其前驱 Box 的阶梯时间间隔」分带，看各带的**胜率 / 每单位净利 / 保本胜率 / 利润集中度 + PF + 剔除前三赢家净利**有没有梯度。
- 这是「Box 生命体征」六体征（出生/成长/阶梯/寿命/死亡/谱系）里的**阶梯**体征，是达瓦斯「箱体像金字塔层层叠加」（L1405）的时间维度量化，不引入任何新理论（`docs/00` §3.6 唯一理论约束）。

### 1.2 本轮明确回答不了的五件事

| # | 回答不了 | 原因 |
|---|---|---|
| 1 | **因果** | 「爬得快/慢」与「突破质量」高度混杂：快梯往往对应强动能股、量比更大（第 7 维）、距新高更近（第 5 维）等。本实验只报**相关性分布**，不下因果结论。 |
| 2 | **阶梯速度该定多少才算「好」** | 本实验是 A 类分带统计（已有交易按阶梯间隔分组），**不改回测器**。若发现某带有 edge，须另立 B 类（改 box 确认/突破节奏重跑），不在本实验范围。 |
| 3 | **样本外有效性** | 2005–2018 是全部参数被选定的同一段历史（`docs/29` §八.6），结论只用于提假设。 |
| 4 | **其他五体征** | LB-1（寿命，已收官）/ LB-4（成长速度）/ LB-5（谱系深度）/ LB-3（出生方式）/ LB-6（死亡模式）不在本实验，LB-2 只做阶梯速度。 |
| 5 | **2019+ 样本** | 规则定稿前禁碰（`docs/29` §八.6）。 |

### 1.3 结论句式模板（强制措辞）

跑完写结论时，必须按以下句式组织，不得省略括号内的限定项：

## §2 实验假设（可证伪形式）

> **口径前置说明**：本实验的「阶梯速度」是**入场 Box 相对其前驱 Box 的台阶时间间隔**，不是 LB-1 的「寿命」（box 自身 confirmed→broken 的存续时间），也不是「持仓持有天数」。
> 三者是不同概念：寿命 = 一个 box 自己活了多久；阶梯速度 = 相邻两个 box 之间隔了多久；持仓天数 = 买入到卖出隔了多久。
> 本实验研究「阶梯速度」与「这笔买入的质量」的关系。

| 编号 | 假设 | 判据（同时满足才算成立） | 证伪条件 |
|---|---|---|---|
| **H1** | **阶梯速度与突破质量单调相关**：爬得越快的 box（阶梯间隔越短），突破后交易质量越高 | L1 四带的每单位净利，4 个相邻对中 **≥ 3 个**随阶梯速度递减（即间隔越短每单位净利越高，严格小于） | 递减对 < 3 → **不成立**（记为「无单调梯度」） |
| **H2** | **快梯突破质量差**：阶梯间隔 <15 交易日的 box（「刚突破上一级就马上突破本级」），突破后是负 edge | `<15 日` 带的每单位净利 **< 0**，且该带 `n ≥ 30`，且剔除前三赢家后净利仍 **< 0** | `<15 日` 带每单位净利 ≥ 0，或剔除前三翻正 → **不成立** |

**H1 与 H2 不是互补关系。** H1 关心「全谱有没有单调梯度」，H2 关心「最左端那一带是不是坑」。可以 H1 不成立但 H2 成立（只有快梯 box 特别差、其余打平），也可以都成立/都不成立。裁定允许四种组合，**禁止**为叙事漂亮压成二选一。

**方向约定（H1 的「递增」方向）**：本实验假设方向是**阶梯间隔越短（爬得越快）质量越高**，即每单位净利随间隔**递减**。故 H1 的判据写成「≥3 个相邻对随间隔递减」，与 LB-1 的「随寿命递增」方向相反——因为 LB-1 实证了「寿命越短越好」，据此提出 LB-2 的「快梯更好」方向假设（假设继承自 LB-1 结论，但**判据方向在跑数前写死**，不得看结果调整）。

**判据阈值（≥3 递减对 / <15 日每单位 <0 / n≥30）在跑数之前写死**，不得看结果调整。

## §3 数据准备过程

### 3.1 只读纪律

- 一律用 `sqlite3.connect("file:<db>?mode=ro", uri=True)`。
- 不写回测库、不碰生产库 `darvas.db`（`docs/06` §6.2 库隔离）。

### 3.2 取数口径

**关联链**（`entry_box_id` 在新基线库全为 NULL，须反向匹配，见 §3.3；沿用 LB-1 已验证的关联键）：

```
position ──leg_no=1──▶ position_leg ──plan_order_id──▶ plan_order
   │                                                      │
   │ status='closed'                                      │ reason_json.box_top / box_bottom
   │ realized_pnl                                         │ signal='breakout'
   ▼                                                      ▼
  交易样本                                      code + box_top + box_bottom
                                                        │ 精确匹配
                                                        ▼
                                                    box 表（入场 Box）
                                                        │ prev_box_id（前驱）
                                                        ▼
                                               前驱 Box 的 broken_date（上一级突破日）
                                                        │
                                           阶梯速度 = 当前 broken_date − 前驱 broken_date 的交易日数
```

单库两条 SQL：

```sql
-- ① 交易样本（复用 LB-1/P2-5 的成本口径：cost_basis 从 legs 求和，position.qty 平仓后清零）
SELECT p.id, p.code, p.realized_pnl, p.close_reason,
       tp.execute_date AS ex_date, o.reason_json,
       (SELECT SUM(qty)       FROM position_leg WHERE position_id=p.id) AS qty,
       (SELECT SUM(qty*price) FROM position_leg WHERE position_id=p.id) AS cost_basis
FROM position p
JOIN position_leg l ON l.position_id=p.id AND l.leg_no=1
JOIN plan_order o ON o.id=l.plan_order_id
JOIN trade_plan tp ON tp.id=o.trade_plan_id
WHERE p.status='closed'

-- ② 入场 Box 匹配（用 reason_json 里的 box_top/box_bottom 精确匹配，含 prev_box_id）
SELECT id, prev_box_id, bottom_confirmed, broken_date, top, bottom, status
FROM box WHERE code=? AND ABS(top-?)<1e-6 AND ABS(bottom-?)<1e-6 AND status='broken_up'

-- ③ 前驱 Box 的突破日（沿 prev_box_id 取前驱的 broken_date）
SELECT broken_date FROM box WHERE id=?

-- ④ 阶梯速度交易日计数（该 code 的 daily_bar 在 [前驱 broken_date, 当前 broken_date] 的行数）
SELECT COUNT(*) FROM daily_bar
WHERE code=? AND date>=? AND date<=?
```

提取字段：

| 字段 | 来源 | 用途 |
|---|---|---|
| `year` | 库文件名 `bt_baseA_<year>.db` | 逐年分组 |
| `realized_pnl` | `position` | 实际盈亏（净额，含双边费用） |
| `qty` / `cost_basis` | `position_leg` 求和 | 成本口径（§3.3 陷阱） |
| `units` | `reason_json.units` | 每单位净利分母 |
| `box_top` / `box_bottom` | `reason_json` | **反向匹配 box 的键** |
| `prev_box_id` | `box` | 前驱箱体（阶梯锚点） |
| `prev_broken_date` | ③ 前驱 box | 阶梯速度起点（上一级突破日） |
| `broken_date` | `box` | 阶梯速度终点（本级突破日） |
| `ladder_gap` | ④ 计数 | 阶梯速度 = 当前 broken_date − 前驱 broken_date 的交易日数 |
| `newhigh_distance_pct` | `reason_json` | 附录切片（与第 5 维交叉） |

### 3.3 两个必须绕开的陷阱

**陷阱一：`entry_box_id` 在新基线库全为 NULL。** 与 LB-1 同因（`ledger.go:405 reasonBoxID` 读的 `box_id` 字段在现行新基线二进制里是死代码路径，planner 没写）。
**绕开方式**：用 `reason_json` 里的 `box_top` / `box_bottom` + `code` 三元组反向精确匹配 box 表（LB-1 已证唯一命中率 100%）。

**陷阱二：`position.qty` 在平仓后被清零。** 成本一律从 `position_leg` 求和（`cost_basis = Σleg.qty×leg.price`），与 LB-1/P2-5 同口径。

### 3.4 反向匹配与前驱链的唯一性验证（HARD 前置）

- `(code, box_top, box_bottom)` 三元组在 box 表里的命中必须是唯一的。多命中取 `broken_date` 最新（与 LB-1 同规则），仍不唯一则标「匹配失败」。
- **前驱链完整性**：匹配到入场 box 后，若 `prev_box_id` 非 NULL，前驱 box 必须存在且 `broken_date` 非空（HARD 校验）；断链（前驱被删除，`docs/36` 缺口 L5）则标「前驱断链」，进不可复算登记。
- 实测（§3.2 前）2015 库 19363 个 prev 非 NULL 的 broken_up box，前驱**全部存在且有 broken_date**，时间顺序**全部合法**（前驱 broken_date ≤ 当前 broken_date，0 异常）。

### 3.5 阶梯速度的口径边界（`docs/36` 第六法）

- **起点 = 前驱 box 的 `broken_date`**：上一级箱体突破的那一天。
- **终点 = 当前 box 的 `broken_date`**：本级箱体突破的那一天。
- **阶梯速度 = [前驱 broken_date, 当前 broken_date] 区间内该股 daily_bar 的行数（含两端）**。
  含义 = 「从上一级突破到本级突破，中间隔了多少个交易日」。
- **首级箱体（`prev_box_id` 为 NULL）无前驱** → 阶梯速度不可算，单设「首级箱体」子集行（不参与四带）。
- **800 根窗口左截断**：`docs/36` 缺口 L4——若前驱 box 落在窗口左边界之外，`prev_box_id` 可能为 NULL（被误判为「首级」），
  或前驱被删除导致断链。这是本实验的已知系统性偏差（会**低估**阶梯链的长度），登记在 §9，结论章必须携带。

### 3.6 样本漏斗（跑前登记，结构锚点）

| 步 | 说明 | 预期 |
|---|---|---|
| 1 | 14 个回测库（2005–2018） | 14 库 |
| 2 | `status='closed'` 且有 leg1 | **1481 笔**（LB-1 §0 实测锚点） |
| 3 | reason_json 缺 `box_top`/`box_bottom`（非 breakout 信号） | 登记，不进阶梯速度分带 |
| 4 | 反向匹配 box 失败（无唯一命中） | 登记「不可复算」，不进阶梯速度分带 |
| 5 | **首级箱体**（prev_box_id 为 NULL） | 单设「首级箱体」子集行，不进四带 |
| 6 | 前驱断链（prev 非 NULL 但前驱不存在/broken_date 空） | 登记「不可复算」，不进阶梯速度分带 |
| 7 | **可复算阶梯速度样本** | 待跑数，见报告 |

### 3.7 已知数据偏差（结论必须携带）

- **未复权（`adj_factor` 恒 1.0）**：box 的 top/bottom 是未复权价，匹配不受影响（都是同一时刻未复权价）；但跨除权日的 box 边界本身可能有语义噪声。
- **800 根窗口左截断**（§3.5）：阶梯链被系统性低估长度，首级箱体可能被高估。
- **幸存者偏差**：只用当前仍存在的股票，退市股不在样本内。
- **无基线对照不构成缺口**：本实验只统计新基线自身，与账本基线（1328 笔）是不同仓位语义，不横比（`docs/29` §〇）。

## §4 口径定义

### 4.1 核心两式

```
ladder_gap = 该 code 的 daily_bar 在 [前驱 broken_date, 当前 broken_date] 的行数（含两端）
pu         = realized_pnl / units          # 每单位净利（units 取自 reason_json.units）
```

### 4.2 为什么阶梯速度用「交易日计数」而不用「自然日相减」

与 LB-1 §4.2 同：达瓦斯箱体的推进是**逐交易日**的，停牌期间 box 不推进，自然日相减会把停牌天数误算进阶梯间隔。故用 `daily_bar` 行数计数，与引擎语义一致。

### 4.3 统计口径（每带必须齐备，与 LB-1 / P0-1 / P2-5 同构）

| 口径 | 公式 | 备注 |
|---|---|---|
| 胜率 | `wins / closed` | 已平仓头寸中盈利占比 |
| 每单位净利 | `Σpnl / Σunits` | `units` 集合 ⊆ {0.5, 1, 2, 3} |
| 保本胜率 | `1 / (1 + 平均盈利/|平均亏损|)` | 即 `|avgLoss| / (avgWin + |avgLoss|)` |
| 利润集中度 | 前三赢家合计 / 毛盈利 | 无毛盈利或前三合计为负时记 `—` |
| 附加 A | 利润因子 PF = 毛盈利 / |毛亏损| | |
| 附加 B | **缺口** = 实际胜率 − 保本胜率（pp） | `docs/29` §八.2 判定用 |
| 附加 C | **剔除前三赢家净利** | 识破「假 edge」的关键列 |
| 附加 D | 剔除前三赢家每单位净利 | 同上 |

### 4.4 分带驱动变量（阶梯速度）

`ladder_gap` 分四带（§5.1）。本实验**不做**「阶梯速度 vs 寿命」「阶梯速度 vs 谱系深度」的交叉（那是 LB 系列内部交叉验证，留待 LB-5 谱系深度做完后联验），只报阶梯速度这一个分组变量（OFAT，`docs/29` §2.3）。

## §5 分带设计

### 5.1 主带：阶梯速度四带（预设规则，禁止按结果合并）

```
[1,15)  [15,30)  [30,60)  [60,+∞)
```

即 **<15 交易日 / 15–30 交易日 / 30–60 交易日 / >60 交易日**。

**切法说明**：15 日 ≈ 三周、30 日 ≈ 一个半月、60 日 ≈ 一季度，是 A 股行情节奏的自然分界，且与 LB-1 的「10/30 日」分界精神一致（都是自然时间尺度）。**这些边界是预设的固定值，不是拟合拐点。**
（数据可行性探测仅用于确认「四带不会出现空箱」，实测 <15 带 88 笔、15-30 带 473 笔、30-60 带 651 笔、>60 带 260 笔，全部 ≥30 笔，非空。）

### 5.2 样本不足的加密规则

- 若某带 `n < 30`，按 §7.1 标「样本不足」，**不合并**（`docs/29` §2.5.1 第 4 条）。
- **不做 L2/L3 二级加密**（阶梯速度是离散交易日，四带已足够，加密只会产生空箱）。若结果出现「某带每单位净利异常高、集中度 >50%、剔除前三翻负」，按 §7.3 直接裁定为「假 edge」，不再降粒度。

### 5.3 空带、首级箱体与不可复算样本的呈现规则

- **首级箱体**（prev_box_id 为 NULL）**不进四带**，单设「首级箱体」子集行，标注「子集标记，非加总行」，印出它自己的笔数、胜率、每单位净利。
- **不可复算样本**（reason_json 缺 box 字段 / box 匹配失败 / 前驱断链）**不进四带**，单设「不可复算」子集行，标注「子集标记，非加总行」。
- 加总恒等式：`Σ(阶梯速度四带 n) + 首级箱体 n + 不可复算 n = 1481`。

### 5.4 逐年矩阵

14 年 × 4 带，每格印「净利（笔数）」。缺失年份登记原因，**不得留空**（HARD 校验 §7.5）。

## §7 判定标准

### 7.1 三条硬门槛（缺一不得下结论）

1. **样本量**：`n ≥ 30`；不足则标「样本不足，仅供参考」。
2. **有样本年数**：`Mf ≥ 8`（过滤后「该年该带 n≥3」的年数）；不足则标「出现年数不足，不作跨年裁定」。
3. **完整性**：四项固定口径 + PF + 缺口 + 剔除前三，缺一项即不得下结论。

### 7.2 跨年一致性记账规则

- `M` = 该带 `n > 0` 的年数；`P` = 该带年度净利 > 0 的年数。
- **过滤后符号统计**：只把「该年该带 `n ≥ 3`」的年计入 `P'` / `M'`，**判定用过滤后那一组**。
- 记分卡必须**同时印出** `P/M` 与 `P'/M'`。
- `longest_run` = 最长连续同号年数（对应 `docs/29` §八.3「连续 ≥2 年同符号」）。

### 7.3 逐带裁定矩阵（与 LB-1 / P0-1 同构，便于横向对比）

| 条件 | 裁定标签 |
|---|---|
| `n < 30` | **样本不足** |
| `n ≥ 30` 且 `Mf < 8` | **出现年数不足** |
| `n ≥ 30`、`Mf ≥ 8`、`pos_ratio' ≥ 0.70`、缺口 ≥ +2pp、剔除前三仍为正 | **edge** |
| 同上但剔除前三为负 | **假 edge（少数交易撑起）** |
| `pos_ratio'` 在 0.30–0.70 | **不稳定（不得下 edge 结论）** |
| `pos_ratio' ≤ 0.30`、缺口 ≤ −2pp | **负 edge** |

判定顺序：**先查剔除前三是否翻负（假 edge）→ 再查跨年稳定性**（P0-1 附 A 方法论修正 1，本实验继承）。
补充：缺口在 ±2pp 之间一律记「无 edge」。

### 7.4 H1 / H2 的裁定输出

两条假设**各自独立裁定**，输出格式固定为：

```
H1 [成立/不成立]  递减相邻对 __/4（需≥3）  四带每单位净利 __ / __ / __ / __
H2 [成立/不成立]  <15 日带每单位净利 __（需<0）  n=__（需≥30）  剔除前三 __（需<0）
```

### 7.5 HARD 校验（生成器必须断言，失败即中止）

| # | 校验 | 判据 |
|---|---|---|
| HARD① | **样本总对账**：Σ 各库 closed 笔数 = 1481 | 严格相等 |
| HARD② | **加总恒等式**：Σ(四带 n) + 首级箱体 n + 不可复算 n = 1481 | 严格相等，不静默丢弃 |
| HARD③ | **逐年符号表齐备**：2005–2018 每年都在矩阵里 | 14 行齐全 |
| HARD④ | **反向匹配唯一性**：每笔可复算样本的 box 匹配命中 = 1（多命中按 §3.4 规则取最近） | 失败 0 笔 |
| HARD⑤ | **前驱链完整**：prev 非 NULL 的入场 box，前驱存在且 broken_date 非空 | 断链 0 笔 |
| HARD⑥ | **阶梯速度非负**：`ladder_gap ≥ 1`（前驱 broken_date ≤ 当前 broken_date） | 0 笔为负 |
| HARD⑦ | **成本两路一致**：`avg_cost×qty` vs `Σ(qty×price)` | 相对误差 < 1e-3 |
| HARD⑧ | **逐年净利对账**：Σ 各年 `realized_pnl` = +1,461,228.2（容差 1.0） | 见 §7.6 锚点 2 |

WARN 级（不中止，但必须出现在报告附 A）：阶梯速度各带笔数分布是否极端不均、800 根窗口左截断影响的首级/断链 box 数量。

### 7.6 校准锚点（生成器每次必须断言）

> **诚实声明**：本框架登记时只做过**结构级**可行性探测（样本 1481 / 阶梯速度可算 1472 / 首级箱体 9 /
> 前驱链完整 / 分带非空），**未看过任何阶梯速度分带的盈亏结果**。以下锚点全部是结构性的：

1. 已平仓样本 = **1481**
2. `Σrealized_pnl = +1,461,228.2`（容差 1.0）
3. 单腿头寸占比 = **100%**（`legs_per_position` 全为 1）
4. `units` / `box_top` / `box_bottom` 缺失笔数 = **0**（实测齐备）
5. 首级箱体（prev_box_id 为 NULL）笔数 ≈ **9**（结构性锚点，容差 ±5）

**执行中的方法论修正与结构性发现**：

1. **前驱链完整性 100%**：19363 个 prev 非 NULL 的 broken_up box，前驱全部存在且有 broken_date，时间顺序全部合法（0 异常）。`prev_box_id`（局部 ID 0 → DB 存 NULL，`repo_box.go:92`）作为阶梯锚点可靠可回溯。

2. **首级箱体占比极低（9/1481 ≈ 0.6%）**：系统几乎从不买入「无前驱的第一级箱体」——因为入场信号要求「距 52 周新高 ≤40%」且「升势」，这些票几乎必然已经历过至少一次箱体突破。首级箱体是结构性边缘样本，不构成独立分析单元（n=9，样本不足）。

3. **阶梯速度与寿命（LB-1）是不同量级**：阶梯间隔中位 35 日（p25=23 / p75=51），远大于寿命中位约 10 日。因为阶梯间隔 = 上一级 broken_up 到本级 broken_up，中间包含了「上一级的形成+确认+等待突破」的完整生命周期，天然比单个 box 的 confirmed→broken 存活期长。这印证了框架 §2 的「三者（寿命/阶梯速度/持仓天数）是不同概念」前置声明。

4. **结果方向与 LB-1 部分呼应、部分背离**：LB-1 证「寿命越短越好」（单调递减）；LB-2 证「阶梯越快越好」只成立一半——最快梯（<15 日）确实最好（+2,634），最慢梯（60 日+）确实最差（+191），但中间两带（15-29 日 +654 vs 30-59 日 +694）几乎打平，方向不单调。且最快梯带（1-14 日）集中度 70.7%、剔除前三仅 +31,827，与 LB-1 的「1-2 日带集中度 83% 剔除前三翻负」是同一类「少数赢家撑起」的假 edge 形态。**两个端带（最快 +2,634 / 最慢 +191）都是假 edge，只有中间两带剔除前三仍为较大正值（+107,660 / +295,721）。**
