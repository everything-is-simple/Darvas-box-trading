## 1 为什么是它（而且是第一位）

### 1.1 事实：生产语义已改，但从未跨年验证

2026-10-27 的 `caac49f` + migration `0018` 把仓位语义整体换掉了：

| 项 | 旧语义（14 年历史库） | 新语义（0018 起） |
|---|---|---|
| 组合约束 | `pool.max_hold = 7`（只数上限） | `pos.equity_gate = on`：总仓位 ≤ **50%** 权益 |
| 单笔上限 | 单位仓 1/2/4/6% | `min(单位仓, 50% 剩余额度, 单票 8%)` |
| 挂单 | **不计入**占用 | **生成即预占**（撤单/过期释放） |
| max_hold 默认 | 7 | **0 = 废止** |

**这套新语义只有一个季度的实证**（2007Q1）：旧口径 7 只 / 暴露 24.3% → 新口径 16 只 /
暴露 35.4% / 单票 6.44% / 119 次拦单。**没有跨年、没有跨市况、没有回撤对照。**

### 1.2 为什么必须排在所有实验之前

`docs/29` §〇 写死了三层基线：

1. **账本基线** `bt_e17_<year>.db` —— 旧语义，所有已发表实验的事实源；
2. **擂主 baseline+** —— 复利链 2,961,561（CAGR 8.06%、MDD −8.03%）；
3. **生产语义** —— 与账本基线**不可比**。

**B-4 跑完才能把 ③ 立为新基线**。在它之前做的任何 B 类实验（P2-6a / P1-4 / P2-6b），
都只能挂在旧语义或"不可比"的语义上，结论无法与擂主对账。这就是"解锁器"的含义：
**它不是最有价值的实验，但它是让后续实验可判定的前提。**

### 1.3 已知的两个真实风险（写进判据，不是免责声明）

1. **暴露上升会放大"买错"**：P0-3 已证「卖晚」不成立（上→下 +57,001），
   **买错才是出血口（下→下 −297,560）**。新语义把同时持仓数从 ~7 提到 ~16，
   等于把"买错"的样本量翻倍 —— 若入场端没有 edge，放大暴露只是放大亏损。
2. **闸门可能在结构市误伤**：2013（脱钩牛）是历史拦截最狠的一年。
   若 50% 预算在该年把有效信号挡在门外，会出现"牛市跑输"的特征形态。

## 2 变体设计（跑前写死）

### 2.1 三个变体

| 变体 | `pos.equity_gate` | `pool.max_hold` | 语义 | 角色 |
|---|---|---|---|---|
| **① 旧语义** | `off` | `7` | 只数上限 7，无预算约束 | **对照锚**（对标 14 年历史库） |
| **② 过渡** | `off` | `14` | 只数上限翻倍，仍无预算 | 分离「只数上限」与「预算闸门」的作用 |
| **③ 新默认** | `on` | `0` | 50% 预算 + 单票 8% + 挂单预占 | 生产语义，待立为新基线 |

### 2.2 为什么必须有 ①（而不只是 ③ vs 历史库）

历史库是**另一个二进制**跑出来的。用 ③ 直接比历史库，差异里混着
"仓位语义"与"二进制其他改动"两个因素 —— 无法归因。
① 用**同一个新二进制**把语义调回旧值，是唯一能隔离变量的做法。

### 2.3 为什么保留 ②（max_hold=14）

③ 相对 ① 同时动了两件事：**去掉只数上限** + **加上 50% 预算**。
②（只把上限翻倍、不启用预算）能回答："若只是放宽只数，结果会怎样？"
- ② ≈ ① 且 ③ ≠ ① → 差异来自**预算闸门**；
- ② ≠ ① 且 ③ ≈ ② → 差异来自**只数上限**（即 7 太紧），预算不是主因。

**没有 ② 就无法区分这两种机制**，只能知道"新语义更好/更差"，不知道为什么。

### 2.4 明确不做什么

- 不改 `pos.equity_limit`（0.5）/ `pos.single_limit`（0.08）——变体只动 §2.1 两参数；
- 不改 `position.staledays`（保持基线 2）——那是 P2-6a；
- 不改入场端任何参数（阶梯 `pos.newhigh.*` 从基线库读）；
- 不做 14 年全铺（12 跑 × 1.2h ≈ 14h 已是上限）。

| 项 | 值 |
|---|---|
| 二进制 | `var/bt/darvas_b4.exe`（2026-10-27 21:30 由**当前 HEAD** 编译，含 0018 + `f6a4c4c`） |

| 输出 | `var/bt/p4/p4_v<k>_<year>.db`（独立 scratch，**绝不覆盖** `bt_e17_<year>.db`） |
| 执行器 | `scripts/p4_run.py`（串行、失败即停、参数从基线库读不手抄） |

**为什么必须用新二进制**：B-4 测的就是 0018 新语义。用 `darvas_e17.exe`（P2-6a 所用）
根本跑不出 ③。这与 P2-6a 的选择正好相反，两者不可混用。

### 3.2 单变量纪律

`--set` 只传三类：`pos.newhigh.*` + `position.staledays`（从基线库读，固定）
+ `pos.equity_gate` / `pool.max_hold`（按变体，本次变量）。

**不得回灌基线库 param 表全部 39 项**：其中混有引擎运行时回写状态（如 `regime.bear_thresh`），
回灌等于把"运行后状态"当初始值。

### 3.3 代表年（跑前写死规则 + 已选结果）

选择规则（预设，不按结果挑）：
1. 覆盖四种市况，且每种只取一个代表年；
2. 该年 `closed` ≥ 60 笔；
3. 单年单档 ≤ 2h。

| 年 | 市况 | 选择理由 |
|---|---|---|
| **2007** | 单边牛 | 暴露不足会少吃 —— 闸门 ③ 的**上行情景** |
| **2010** | 震荡 | 中性基准，四类市况里最"无偏"的一年 |
| **2013** | 脱钩牛 | **历史拦截最狠年**，闸门误伤风险最高（§1.3 风险 2） |
| **2018** | 熊市 | 暴露上升放大亏损的**下行情景**（§1.3 风险 1） |

### 3.4 成本与阶段

单年单档 1–2h。**12 跑 ≈ 14h**，通宵串行。

阶段划分（先证锚，再铺开）：
- **阶段 0（锚验证）**：2007 × ①，≈1.5h → 跑 HARD①；
- **阶段 1（筛选）**：若 HARD① 通过 → 2007/2010/2013/2018 × ②③（8 跑 ≈10h）；
- **阶段 2（确认）**：胜出变体补 2 年（2011/2015），仅在阶段 1 结论贴边时才做。

## 4 指标（每变体每年必报）

### 4.1 主判据（擂台规则，`docs/29` §〇.1）

1. **代表年链接复利终值** `Π(1+r_y)`，不比单年 `eq_end`；
2. **代表年最大回撤**（各年 `maxdd_pct` 最差值）；
3. **Calmar** = 复利年化 / MDD。

### 4.2 结构指标（判"怎么变的"，不给分）

| 指标 | 定义 | 为什么看 |
|---|---|---|
| 平均持仓数 | `Σ持仓日数 / 交易日数` | 语义是否真的生效（③ 应显著高于 ①） |
| 日均暴露 | `Σ持仓市值 / Σ权益 / 交易日数` | 是否真的逼近 50%（0018 的设计目标） |
| 单票最大占比 | 单笔市值 / 权益 的最大值 | 是否触到 8% 上限 |
| 拦单数 | `equityBudget` 拒绝的买单数 | 闸门的实际作用面 |
| 大赢家保留率 | MFE>50% 笔数与该批净利 | **防切碎**：46 笔贡献 +1,133,049 |
| 短持块净利 | 持有 ≤10 日已平仓合计 | P2-5 的 −996,930 是否被放大 |
| `ts_n` / `ts_share` | time_stop 出口 | staledays=2 固定，应基本不变（作为"没串变量"的证据） |

### 4.3 四项固定口径（与 P0-1/P0-3/P2-5 同源，便于横比）

胜率 / 每单位净利 / 保本胜率 / 利润集中度（前三赢家占比）+ **剔除前三赢家净利**。

## 5 判定（预注册）

### 5.1 三条假设

- **H1（新语义更优）**：③ 复利终值 > ① **且** MDD 不更差（差值 ≤ +0.5pp）
  → 采纳 ③，**立为新账本基线**，此后所有 B 类对照以它为锚。
- **H2（新语义中性）**：③ 与 ① 复利终值差 < 3%（噪声口径，同 P2-6a §5.2）
  → **仍立 ③ 为新基线**（工程上更干净：只数上限与预算不兼容，且 0018 已落地），
  但登记「新语义无收益改善，仅语义统一」，**不得表述为"优化"**。
- **H3（新语义有害）**：③ 复利终值 < ① **且** MDD 更差（> 0.5pp）
  → **不采纳**，写 migration 回滚 `pos.equity_gate=off` + `pool.max_hold=7`，
  并登记 0018 的设计假设（"7 × 2.6% ≈ 18% 吃不满 50%"）在真实数据上不成立。

**三选一必居其一。** 非单调（如 ② 最好）→ 按 H2 处理并登记"机制可分离但结论不稳定"，
不得挑单点最优变体。

### 5.2 显著性口径

- 复利终值差 < 3% → 噪声，不构成采纳依据（只支持 H2）；
- 任一变体任一年 `closed` < 60 → 该年标"样本不足"，不参与判定；
- **代表年方向不一致**（如 2007 支持 ③、2018 反对）→ 判定"无稳定结论"，按 H2 处理，
  且必须在报告中列出逐年符号表，不得用合计掩盖。

### 5.3 采纳的工程代价

- 若 H1 成立：写 migration 声明"新基线 = 0018 语义"，并在 `docs/29` §〇 更新第二层基线值；
- 若 H3 成立：写 migration 回滚（append-only，不删 0018）；
- 两种情况都**不得修改** `bt_e17_<year>.db` 历史库。

## 6 HARD 校验（全跑前写死）

| # | 校验 | 通过标准 |
|---|---|---|
| ① | **① 变体复现历史** | `p4_v1_2007.db` 与 `bt_e17_2007.db` 对账：`closed` 笔数、`Σrealized_pnl`、逐笔 `code+opened_date+closed_date+pnl`（容差 0.01 元）。**判定规则见 §6.2** |
| ② | 参数生效 | 各库 `param.pos.equity_gate` / `pool.max_hold` = 变体目标值 |
| ③ | 单变量 | 各库除上述两参数外，其余 param 与①逐项相同 |
| ④ | 合计闭合 | 各库 `closed` + 未平仓 = 建仓总数，不静默丢弃 |
| ⑤ | 结论可复算 | 复利终值/MDD/暴露由 `scripts/p4_report.py` 从库直算，报告数字与 JSON 一致 |
| ⑥ | 齐备 | 每个变体每年都有产物与耗时，缺档登记原因 |

### 6.2 ⚠️ HARD① 不通过时的处理规则（**跑前写死，最重要的一条**）

**已知风险**：`max_hold` 的计数口径是 `openCount + pendingBuys`（`planner.go:107`），
而 `f6a4c4c` 修过 `PendingBuyCount`。因此 ① 在新二进制上**有可能无法逐笔复现历史库**——
这不是 bug，是两个已登记 commit 的预期后果。

**处理规则（二分，不得临时找理由）**：

| 情形 | 判据 | 处理 |
|---|---|---|
| **A. 完全复现** | 逐笔全等 | ① 可信；②③ 与 ① 的差异，也可与 14 年历史库直接横比 |
| **B. 不完全复现** | 差异存在，但差异**方向与量级**能归因到 `f6a4c4c`（挂单预占）/`caac49f`（预算）/`0018` | ① 降级为"**新二进制下的旧语义锚**"：①②③ 之间仍**完全可比**（同一二进制、同一 commit），但 **① 的绝对值不得与 14 年历史库横比**，报告须显著标注 |
| **C. 差异无法归因** | 出现与上述三项无关的笔数/金额差异 | **整个实验作废**，先查二进制/参数/迁移，不得继续 |

**为什么这条必须跑前写死**：跑完发现不一致时，"这大概是挂单预占的影响"是
最容易被接受、也最容易被滥用的解释。先写死判据，才能避免事后合理化。
