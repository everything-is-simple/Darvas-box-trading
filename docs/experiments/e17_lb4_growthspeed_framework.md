## §1 实验目的与边界声明

### 1.1 本轮要回答的一个问句

box 的**成长速度**（从「上轨 3 日确认」到「下轨 3 日确认」的交易日跨度 = 轨确认延迟）与**突破后这笔交易的质量**是什么关系？

- 具体化：把每一笔已平仓交易的「入场 Box 的轨确认延迟」（`top_confirmed → bottom_confirmed` 的交易日数）分带，看各带的**胜率 / 每单位净利 / 保本胜率 / 利润集中度 + PF + 剔除前三赢家净利**有没有梯度。
- 这是「Box 生命体征」六体征（出生/成长/阶梯/寿命/死亡/谱系）里的**成长**体征，量化「箱体两条轨道从确认到闭合花了多久」，不引入任何新理论（`docs/00` §3.6 唯一理论约束）。
- **与 LB-1 / LB-2 / LB-5 的区分**：LB-1 测「box 从下轨确认到突破活多久」（confirmed→broken）；LB-2 测「相邻两级台阶隔多久」（前驱 broken→当前 broken）；LB-5 测「第几级箱体」（位置）。LB-4 测的是**箱体内部成型期的速度**（top_confirmed→bottom_confirmed），四者是四个不同的时间/位置量。

### 1.2 本轮明确回答不了的五件事

| # | 回答不了 | 原因 |
|---|---|---|
| 1 | **因果** | 「轨确认延迟」与「突破质量」高度混杂：更慢的确认往往对应更犹豫的筹码结构、更接近第 5 维距新高的位置、更大的量比等。本实验只报**相关性分布**，不下因果结论。 |
| 2 | **成长速度该定多少才算「好」** | 本实验是 A 类分带统计，**不改回测器**。若发现某带有 edge，须另立 B 类，不在本实验范围。 |
| 3 | **样本外有效性** | 2005–2018 是全部参数被选定的同一段历史（`docs/29` §八.6），结论只用于提假设。 |
| 4 | **其他五体征** | LB-1（寿命）/ LB-2（阶梯速度）/ LB-5（谱系深度）已收官；LB-3（出生方式）/ LB-6（死亡模式）不在本实验，LB-4 只做成长速度。 |
| 5 | **2019+ 样本** | 规则定稿前禁碰（`docs/29` §八.6）。 |

### 1.3 结论句式模板（强制措辞）

> 在 2005–2018 的 __ 笔已平仓交易中，可复算成长速度 __ 笔、不可复算 __ 笔；成长速度四带（4–5 / 6–7 / 8–10 / 11+ 日）的每单位净利分别为 __ / __ / __ / __，胜率 __ / __ / __ / __。
> H1（成长速度与突破质量单调相关）**成立/不成立**；H2（慢速确认箱体突破质量差）**成立/不成立**。
> 「成长速度该定多少阈值」**本实验不回答**，只能由后续 B 类回测回答。

禁止出现的写法：`越快越好`、`该在快速确认箱体买`、`等到慢速确认箱体再进`。

## §2 实验假设（可证伪形式）

> **口径前置说明**：本实验的「成长速度」是**入场 Box 从 `top_confirmed`（上轨 3 日确认日）到 `bottom_confirmed`（下轨 3 日确认日）的交易日跨度**，即「箱体两条轨道从确认到闭合花了多少交易日」。
> 它与 LB-1 的「寿命」（bottom_confirmed→broken）、LB-2 的「阶梯速度」（前驱 broken→当前 broken）、LB-5 的「谱系深度」（第几级）、「持仓天数」（买入到卖出）是**五个不同概念**。
> 本实验只研究「成长速度」与「这笔买入的质量」的关系。

| 编号 | 假设 | 判据（同时满足才算成立） | 证伪条件 |
|---|---|---|---|
| **H1** | **成长速度与突破质量单调相关**：更慢的箱体成型（轨确认延迟更长），突破后交易质量越低 | 四带的每单位净利，4 个相邻对中 **≥ 3 个**随延迟递增而递减（即确认越慢每单位净利越低，严格小于） | 递减对 < 3 → **不成立**（记为「无单调梯度」） |
| **H2** | **慢速确认箱体突破质量差**：轨确认延迟 ≥ 11 日的 box，突破后是负 edge | `≥11 日` 带的每单位净利 **< 0**，且该带 `n ≥ 30`，且剔除前三赢家后净利仍 **< 0** | `≥11 日` 带每单位净利 ≥ 0，或剔除前三翻正 → **不成立** |

**H1 与 H2 不是互补关系。** H1 关心「全谱有没有单调梯度」，H2 关心「最右端那一带（最慢）是不是坑」。可以 H1 不成立但 H2 成立，也可以都成立/都不成立。裁定允许四种组合，**禁止**为叙事漂亮压成二选一。

**方向约定（H1 的「递减」方向）**：本实验假设方向是**确认越慢（成长越慢）质量越低**，即每单位净利随轨确认延迟**递减**。这是达瓦斯原书「箱体要紧凑、快速成型才有动能」的直觉延伸——磨磨蹭蹭才闭合的箱体，突破偏钝。但**判据方向在跑数前写死**，不得看结果调整。

**判据阈值（≥3 递减对 / ≥11 日每单位 <0 / n≥30）在跑数之前写死**，不得看结果调整。

## §3 数据准备过程

### 3.1 只读纪律

- 一律用 `sqlite3.connect("file:<db>?mode=ro", uri=True)`。
- 不写回测库、不碰生产库 `darvas.db`（`docs/06` §6.2 库隔离）。
- 不重跑任何回测、不改任何参数、不重建任何索引。

### 3.2 取数口径

**关联链**（`entry_box_id` 在新基线库全为 NULL，须反向匹配，见 §3.3；沿用 LB-1/LB-2/LB-5 已验证的关联键）：

```
position ──leg_no=1──▶ position_leg ──plan_order_id──▶ plan_order
   │                                                      │
   │ status='closed'                                      │ reason_json.box_top / box_bottom
   │ realized_pnl                                         │ signal='breakout'
   ▼                                                      ▼
  交易样本                                      code + box_top + box_bottom
                                                        │ 精确匹配
                                                        ▼
                                                    box 表（入场 Box）
                                                        │ top_confirmed / bottom_confirmed
                                                        ▼
                                       成长速度 = top_confirmed → bottom_confirmed 的交易日数
```

单库两条 SQL：

```sql
-- ① 交易样本（复用 LB-1/LB-2/LB-5/P2-5 的成本口径：cost_basis 从 legs 求和，position.qty 平仓后清零）
SELECT p.id, p.code, p.realized_pnl, p.close_reason,
       tp.execute_date AS ex_date, o.reason_json,
       (SELECT SUM(qty)       FROM position_leg WHERE position_id=p.id) AS qty,
       (SELECT SUM(qty*price) FROM position_leg WHERE position_id=p.id) AS cost_basis
FROM position p
JOIN position_leg l ON l.position_id=p.id AND l.leg_no=1
JOIN plan_order o ON o.id=l.plan_order_id
JOIN trade_plan tp ON tp.id=o.trade_plan_id
WHERE p.status='closed'

-- ② 入场 Box 匹配（用 reason_json 里的 box_top/box_bottom 精确匹配，含 top_confirmed/bottom_confirmed）
SELECT id, top_confirmed, bottom_confirmed, broken_date, top, bottom, status
FROM box WHERE code=? AND ABS(top-?)<1e-6 AND ABS(bottom-?)<1e-6 AND status='broken_up'

-- ③ 成长速度交易日计数
SELECT COUNT(*) FROM daily_bar WHERE code=? AND date>=? AND date<=?
--   date>= top_confirmed 且 date<= bottom_confirmed（含两端）
```

提取字段：

| 字段 | 来源 | 用途 |
|---|---|---|
| `year` | 库文件名 `bt_baseA_<year>.db` | 逐年分组 |
| `realized_pnl` | `position` | 实际盈亏（净额，含双边费用） |
| `qty` / `cost_basis` | `position_leg` 求和 | 成本口径（§3.3 陷阱） |
| `units` | `reason_json.units` | 每单位净利分母 |
| `box_top` / `box_bottom` | `reason_json` | **反向匹配 box 的键** |
| `top_confirmed` / `bottom_confirmed` | `box` | 成长速度的起终点 |
| `growth_speed` | ③ 交易日计数 | 成长速度 = top_confirmed → bottom_confirmed 的交易日数 |
| `newhigh_distance_pct` | `reason_json` | 附录切片（与第 5 维交叉） |

### 3.3 两个必须绕开的陷阱

**陷阱一：`entry_box_id` 在新基线库全为 NULL。** 与 LB-1/LB-2/LB-5 同因（`ledger.go:405 reasonBoxID` 读的 `box_id` 字段在现行新基线二进制里是死代码路径，planner 没写）。
**绕开方式**：用 `reason_json` 里的 `box_top` / `box_bottom` + `code` 三元组反向精确匹配 box 表（LB-1 已证唯一命中率 100%）。

**陷阱二：`position.qty` 在平仓后被清零。** 成本一律从 `position_leg` 求和（`cost_basis = Σleg.qty×leg.price`），与 LB-1/LB-2/LB-5/P2-5 同口径。

### 3.4 反向匹配唯一性验证（HARD 前置）

- `(code, box_top, box_bottom)` 三元组在 box 表里的命中必须是唯一的。多命中取 `broken_date` 最新（与 LB-1/LB-2/LB-5 同规则），仍不唯一则标「匹配失败」。

### 3.5 成长速度的口径边界（`docs/36` 第六法）

- **上轨确认日** = `top_confirmed`（上轨 3 日确认完成日）。
- **下轨确认日** = `bottom_confirmed`（下轨 3 日确认完成日）。
- **成长速度** = `bottom_confirmed → top_confirmed` 之间的**交易日数**（用 `daily_bar` 在 `[top_confirmed, bottom_confirmed]` 闭区间计数，含两端）。
- **时间顺序**：`top_confirmed` 必须先于 `bottom_confirmed`（箱体先见顶、后见底）。顺序异常的样本标「不可复算」。
- **理论下限**：`top_confirmed` 和 `bottom_confirmed` 各需 3 日确认，成长速度天然 ≥ 某最小值（实测最小值 4 交易日，见 §7.6 锚点）。

### 3.6 样本漏斗（跑前登记，结构锚点）

| 步 | 说明 | 预期 |
|---|---|---|
| 1 | 14 个回测库（2005–2018） | 14 库 |
| 2 | `status='closed'` 且有 leg1 | **1481 笔**（LB-1 §0 实测锚点） |
| 3 | reason_json 缺 `box_top`/`box_bottom`（非 breakout 信号） | 登记，不进成长速度分带 |
| 4 | 反向匹配 box 失败（无唯一命中） | 登记「不可复算」，不进成长速度分带 |
| 5 | `top_confirmed` 或 `bottom_confirmed` 缺失 / 顺序异常 | 登记「不可复算」，不进成长速度分带 |
| 6 | **可复算成长速度样本** | 待跑数，见报告 |

### 3.7 已知数据偏差（结论必须携带）

- **未复权（`adj_factor` 恒 1.0）**：box 的 top/bottom 是未复权价，匹配不受影响；但跨除权日的 box 边界本身可能有语义噪声。
- **成长速度受 3 日确认规则刚性约束**：`top_confirmed`/`bottom_confirmed` 都是「连续 3 日」确认的产物，成长速度的量级被确认窗口钳制（实测全样本 4–21 日），分布本身偏窄，梯度分辨率有限。
- **幸存者偏差**：只用当前仍存在的股票，退市股不在样本内。
- **无基线对照不构成缺口**：本实验只统计新基线自身，与账本基线（1328 笔）是不同仓位语义，不横比（`docs/29` §〇）。

## §4 口径定义

### 4.1 核心两式

```
growth_speed = 交易日数(bottom_confirmed → top_confirmed)   # daily_bar 闭区间计数，含两端
pu           = realized_pnl / units                          # 每单位净利（units 取自 reason_json.units）
```

### 4.2 为什么成长速度用「交易日计数」而不用「自然日相减」

成长速度的本质是「箱体成型期经历了多少个交易日」，必须用 `daily_bar` 实际计数（跳过周末/停牌日），不能用 `julianday(bottom_confirmed) − julianday(top_confirmed)`（会混入非交易日）。与 LB-1 寿命、LB-2 阶梯速度的交易日计数口径一致。

### 4.3 统计口径（每带必须齐备，与 LB-1 / LB-2 / LB-5 / P0-1 / P2-5 同构）

| 口径 | 公式 | 备注 |
|---|---|---|
| 胜率 | `wins / closed` | 已平仓头寸中盈利占比 |
| 每单位净利 | `Σpnl / Σunits` | `units` 集合 ⊆ {0.5, 1, 2, 3} |
| 保本胜率 | `1 / (1 + 平均盈利/|平均亏损|)` | 即 `|avgLoss| / (avgWin + |avgLoss|)` |
| 利润集中度 | 前三赢家合计 / 毛盈利 | 无毛盈利或前三合计为负时记 `—` |
| 附加 A | 利润因子 PF = 毛盈利 / |毛亏损| | |
| 附加 B | **缺口** = 实际胜率 − 保本胜率（pp） | `docs/29` §八.2 判定用 |
| 附加 C | **剔除前三赢家净利** | 识破「假 edge」的关键列 |
| 附加 D | 剔除前三赢家每单位净利 | 同上 |

### 4.4 分带驱动变量（成长速度）

`growth_speed` 分四带（§5.1）。本实验**不做**「成长速度 vs 寿命」「成长速度 vs 阶梯速度」「成长速度 vs 谱系深度」的交叉（那是 LB 系列内部交叉验证，留待 LB 系列 A 类全收官后联验），只报成长速度这一个分组变量（OFAT，`docs/29` §2.3）。

## §5 分带设计

### 5.1 主带：成长速度四带（预设规则，禁止按结果合并）

```
[4,6)  [6,8)  [8,11)  [11,+∞)
```

即 **4–5 日 / 6–7 日 / 8–10 日 / 11 日+**。

**切法说明**：成长速度是「箱体两条轨道从确认到闭合的天数」，用 6/8/11 三个界切出「快 / 中 / 中慢 / 慢」四段。**这些边界是预设的固定值，不是拟合拐点。**
（数据可行性探测仅用于确认「四带不会出现空箱」，实测 4–5 日 651 笔、6–7 日 375 笔、8–10 日 307 笔、11 日+ 148 笔，全部 ≥ 100 笔，非空。）

### 5.2 样本不足的加密规则

- 若某带 `n < 30`，按 §7.1 标「样本不足」，**不合并**（`docs/29` §2.5.1 第 4 条）。
- **最右带（11 日+）不再加密**（实测 148 笔已够，且成长速度分布本身偏窄，加密意义有限）。若结果出现「某带每单位净利异常高、集中度 >50%、剔除前三翻负」，按 §7.3 直接裁定为「假 edge」，不再降粒度。

### 5.3 空带与不可复算样本的呈现规则

- **不可复算样本**（reason_json 缺 box 字段 / box 匹配失败 / top_confirmed 或 bottom_confirmed 缺失 / 顺序异常）**不进四带**，单设「不可复算」子集行，标注「子集标记，非加总行」。
- 加总恒等式：`Σ(成长速度四带 n) + 不可复算 n = 1481`。

### 5.4 逐年矩阵

14 年 × 4 带，每格印「净利（笔数）」。缺失年份登记原因，**不得留空**（HARD 校验 §7.5）。

## §7 判定标准

### 7.1 三条硬门槛（缺一不得下结论）

1. **样本量**：`n ≥ 30`；不足则标「样本不足，仅供参考」。
2. **有样本年数**：`Mf ≥ 8`（过滤后「该年该带 n≥3」的年数）；不足则标「出现年数不足，不作跨年裁定」。
3. **完整性**：四项固定口径 + PF + 缺口 + 剔除前三，缺一项即不得下结论。

### 7.2 跨年一致性记账规则

- `M` = 该带 `n > 0` 的年数；`P` = 该带年度净利 > 0 的年数。
- **过滤后符号统计**：只把「该年该带 `n ≥ 3`」的年计入 `P'` / `M'`，**判定用过滤后那一组**。
- 记分卡必须**同时印出** `P/M` 与 `P'/M'`。
- `longest_run` = 最长连续同号年数（对应 `docs/29` §八.3「连续 ≥2 年同符号」）。

### 7.3 逐带裁定矩阵（与 LB-1 / LB-2 / LB-5 / P0-1 同构，便于横向对比）

| 条件 | 裁定标签 |
|---|---|
| `n < 30` | **样本不足** |
| `n ≥ 30` 且 `Mf < 8` | **出现年数不足** |
| `n ≥ 30`、`Mf ≥ 8`、`pos_ratio' ≥ 0.70`、缺口 ≥ +2pp、剔除前三仍为正 | **edge** |
| 同上但剔除前三为负 | **假 edge（少数交易撑起）** |
| `pos_ratio'` 在 0.30–0.70 | **不稳定（不得下 edge 结论）** |
| `pos_ratio' ≤ 0.30`、缺口 ≤ −2pp | **负 edge** |

判定顺序：**先查剔除前三是否翻负（假 edge）→ 再查跨年稳定性**（P0-1 附 A 方法论修正 1，本实验继承）。
补充：缺口在 ±2pp 之间一律记「无 edge」。

### 7.4 H1 / H2 的裁定输出

两条假设**各自独立裁定**，输出格式固定为：

```
H1 [成立/不成立]  递减相邻对 __/4（需≥3）  四带每单位净利 __ / __ / __ / __
H2 [成立/不成立]  ≥11 日带每单位净利 __（需<0）  n=__（需≥30）  剔除前三 __（需<0）
```

### 7.5 HARD 校验（生成器必须断言，失败即中止）

| # | 校验 | 判据 |
|---|---|---|
| HARD① | **样本总对账**：Σ 各库 closed 笔数 = 1481 | 严格相等 |

**执行中的方法论修正与结构性发现**：

1. **H1 成立——这是 LB 系列四个体征里第一个方向单调的**。成长速度四带每单位净利 **+1,015 → +718 → +328 → +320，严格单调递减**（递减相邻对 3/3，需 ≥3）。方向符合预注册假设：箱体成型越快（轨确认延迟越短），突破后每单位净利越高。

2. **4–5 日带是四个体征里唯一「剔除前三后仍成片为正」的强带**：每单位 +1,015 全表最高、PF 2.44 最高、集中度仅 26.1%（远低于其他带）、剔除前三 +487,561 仍大幅为正。这是 LB-1/LB-2/LB-5 端带普遍「少数交易撑起」的反例——快成型箱体的盈利是**成片的**，不是两三笔撑起来的。

3. **H2 不成立但右端带仍是「假 edge」**：11 日+ 带每单位 +320（正的，未达负 edge），但剔除前三 −35,878 翻负、集中度 48.8%——慢成型箱体的表面盈利靠少数赢家撑起。与 LB-1/LB-2/LB-5 的端带「假 edge」形态一致（第五次复现「剔除前三识破假 edge」）。

4. **成长速度分布偏窄被证实**：全样本 4–21 日，中位 6 日、p25=4 / p75=8。受「上/下轨各需 3 日确认」规则刚性钳制，这是 LB 系列里量级最小、分布最窄的一个体征。即便如此，单调梯度依然清晰。
